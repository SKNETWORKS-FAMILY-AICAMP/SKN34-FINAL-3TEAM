# 사고뭉치
아이의 생각을 기록하고, 그 기록을 학부모가 대화로 분석하는 사고력 학습 플랫폼
(과정 공통 주제 "대화형 데이터 기반 분석 에이전트 및 자동 리포팅 플랫폼"을 초~중학생 사고력 학습에 적용)

## 프로젝트 개요
- 사용자: 학생(초3~6 중심) / 학부모 / 관리자(서비스·콘텐츠·결제 운영)
- 핵심 기능: 미션(생각 작성 → 되묻기 → 정답·예시 답 확인·돌아보기), 학부모 대화형 분석 에이전트(학습 기록 조회·계산, 숫자·인용 자동 대조), 주간·일일 리포트 자동 생성, 주간 테마·커뮤니티·포인트·꾸미기·생활공간·추억 검색
- 다섯 가지 생각 유형: 분석하기·따져 보기·새로 만들기·문제 해결하기·돌아보기 (기초 사고력: 비교·분류·순서·규칙·원인과 결과·추론)
- 정책 전체(P01~P16·P19~P28)는 [기능명세 1.4](design/functional-spec.md#14-확정-정책), 정책별 결정 경위는 기능명세 머리말의 정책 출처 표

## 서비스 흐름

### 학생 미션
1. 미션 장면·질문을 보고 답을 쓰거나 고름 (막히면 생각 열기 질문·메모장 활용)
2. 판정: 고르기·수학 최종 답은 규칙, 서술·논술은 채점 기준표 요소별로 LLM이 근거 구절을 찾고 코드가 그 구절이 답에 실제 있는지 확인
3. 결과에 따라 "한 걸음 더" / "더 말해 보기" / "다시 살펴보기" 중 하나로 연결, 근거가 없으면 판정 보류
4. 생각을 다 낸 뒤에만 정답·예시 답과 "들어가면 좋은 생각" 체크 공개, 돌아보기 기록

### 학부모
1. 가입·자녀 등록 시 법정대리인 동의 및 동의 기록 저장
2. 주간·일일 리포트 확인
3. 리포트에 질문 → 에이전트가 학습 기록 조회·계산 후 답변 (숫자·인용 대조 후 제시)

## 구현 제약
- 범위: 초3~6 서술형·논술형 + 다섯 가지 생각 유형 중심 (중·고, 초1~2는 확장)
- 하지 않는 것: 답 대신 써 주기, 맞춤법 교정, 사고력 진단 검사, 성적 향상 보장
- 숫자 레벨은 검증 전까지 학생·학부모에게 비공개
- 답변은 덮어쓰지 않고 버전별 저장
- 학생 이름은 LLM API로 전송 금지
- 12/7 배포는 데모 계정만 운영
- 결제는 토스페이먼츠 테스트 환경(테스트 키)까지만 연동, 실결제 미도입
- API 키는 환경 변수·GitHub Secrets에만 보관
- LLM 호출마다 토큰 사용량 기록 (학생 ID·답변 내용 미기록)

## 개발 규칙

### 작업 규칙
- 모든 코드는 [설계 구조](design/architecture.md)의 서비스 경계·통신 방식·레이어 규칙·디렉토리 구조를 준수
- 설계와 다른 구조가 필요하면 설계 문서를 먼저 갱신한 뒤 구현
- 설계 변경 시 변경 내용과 근거를 `docs/report/`의 해당 주제 보고서에 절로 추가 (새 주제일 때만 새 파일, 파일 이름은 이슈 번호가 아닌 주제명). 새 절은 그 파일의 끝 번호 다음 번호로

### 커밋 규칙

#### 형식
```
type: subject
```

#### type
| type | 용도 |
|---|---|
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 수정 |
| `docs` | 문서 수정 (README 등) |
| `style` | 코드 포맷팅, 세미콜론 누락 (로직 변경 없음) |
| `refactor` | 코드 리팩토링 (기능 변화 없음) |
| `test` | 테스트 코드 추가 및 수정 |
| `chore` | 빌드 스크립트 수정, 패키지 매니저 설정 등 |

#### 예시
```
feat: 데이터셋 업로드 API 추가
fix: 리포트 생성 실패 시 상태 미갱신 수정
docs: 아키텍처 설계 문서 추가
```

### 브랜치 규칙

#### 전략: Git Flow (간소화)
`hotfix/*`, `release/*` 브랜치는 사용하지 않음.

| 브랜치 | 역할 |
|---|---|
| `main` | 배포 기준 브랜치 |
| `develop` | 개발 통합 브랜치 |
| `feature/*` | 기능 개발 브랜치, `develop`에서 분기 |

#### 병합 흐름
```
feature/* → develop → main
```
- `feature/*`는 `develop`으로만 병합
- `main`은 `develop`에서만 병합
- 순서를 건너뛴 병합(`feature/*` → `main`) 금지
- 예외(2026-11-20, #858): `infrastructure/gitops/environments/prod/images/**`**만** 바꾸는 prod digest PR은 `main`에 직접 병합한다. cd-release가 만드는 `cd/prod-images-*` 브랜치 PR, 그 PR의 revert, 비상용 Helm 배포 뒤 값 맞춤 PR이 해당한다. 승인은 CODEOWNERS(김동섭·김태윤) 1명, 절차는 [CD README](../infrastructure/cd/README.md#digest-pr-배포-기본-858)
  - `develop`은 images 파일을 고치지 않는다(#857이 처음 만든 뒤). 그래서 main에 digest 커밋이 쌓여도 `develop` → `main` 릴리스 병합과 충돌하지 않고, main의 배포 값이 유지된다. `develop`의 images 파일은 처음 값으로 남으며 Argo CD는 main만 읽는다
