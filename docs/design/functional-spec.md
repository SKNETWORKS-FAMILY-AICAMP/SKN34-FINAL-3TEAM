### 1.3 공통 처리 규칙
- 권한 검사: 학생은 본인, 학부모는 연결된 자녀 기록만. 화면 요청·에이전트 도구 호출·리포트·다운로드 모두 동일 검사, 다른 식별값 요청은 거부 (FBN-01)
- 수치 근거: 모든 건수·비율은 코드로 계산하고 기간·분자·분모·계산식·출처 유형(기록·규칙·정답 키·AI 관찰)을 함께 제공
- 상태 구분: 기록 없음·표본 부족·판정 보류·처리 실패를 서로 다른 상태로 처리, 확인되지 않은 값을 임의로 채우지 않음
- 효과 표현: 관찰된 답변 변화와 사고력 향상을 구분, 검증 전 숫자 레벨·등급·순위 비표시
- 대체 응답: 1.4 P16에 정한 지점만 허용, 그 외 자동 대체 금지. 대체 시 실패 사실·출처(llm·llm_retry·bank·template)·조회 근거 표시
- 생각 유형: 분석하기·따져 보기·새로 만들기·문제 해결하기·돌아보기 5개를 전 기능 동일 사용, 비교·분류·순서·규칙·원인과 결과·추론은 기초 사고력으로 구분 (FAD-05). 정의·평가 요소·과목 매핑은 1.5

### 1.4 확정 정책

| P | 항목 | 확정 내용 |
|---|---|---|
| P01 | 학생 진입·계정 | 학생 별도 계정(아이디·이메일) 없음. 학생 진입은 ① 학부모 등록 기기에서 자녀 PIN 로그인(학부모 부재 시 단독 학습) ② 학부모 로그인 → 자녀 선택 → 학생 세션 발급(동석 시) 두 경로. 기기 등록은 학부모가 1회 승인, 미등록 기기는 PIN만으로 진입 불가 (2026-10-27 개정, [보고서](../report/auth-account.md)). 시연 링크(`?student=`) 폐지. 자녀 등록 필수: 별명·학년·출생연도. 자녀는 전원 만 14세 미만으로 간주, 등록 시 법정대리인(학부모) 동의 저장 |
| P02 | 보호자 연결·다자녀 | 학생당 현재 보호자 1명, 학부모당 자녀 최대 3명. 임의 중복 연결은 미지원하며 #289의 탈퇴 전 이관은 받는 학부모의 수락·보호자 동의 후 기존 연결을 종료하고 새 연결로 교체한다. 자녀 없는 학부모도 수락 가능. 상단 전역 자녀 전환, 대시보드·대화·리포트 공통, 마지막 선택 자녀 기억 |
| P03 | 학년·문항·음성 | 지원 학년 초3~6(새 등록 범위). 저장 학년은 자동 진급(P26)으로 중3까지 오르며, 중학생은 중학교 과정 확장 전까지 초6 문제를 받는다. 시연 초3·초5 각 5문항(생각 유형별 1문항). 서술·풀이 단계 틀 전 학년, 논술 틀 초5~6. 음성 시범(STT) 미구현, 질문 읽어주기는 브라우저 TTS로 전 학년 |
| P04 | 마무리·되묻기 | 마무리 조건: 판정 처리 완료(`DONE`, 보류 포함) 1회 이상. 되묻기 최대 2회, 도달 시 마무리 안내. 고르기 정답 시 되묻기 없이 즉시 마무리 가능, 되묻기 건너뛰기("이대로 돌아보기") 허용. 마무리 후 답변 제출 불가. 돌아보기는 난이도 필수·달라진 점 선택, 저장 시 학습 완료 |
| P05 | 생각 메모 | 초안과 함께 서버 자동 저장, 학생 본인만 열람(판정·리포트·학부모 화면·분석 대화 미노출) |
| P06 | 리포트 | 주간 리포트: 주 경계 KST 월 00:00~일 23:59:59, 주가 끝난 일요일 자정(월요일 00:00) 생성(2026-11-09 변경). 기록 없는 자녀도 "기록 없음" 리포트 생성(LLM 미호출). 이번 주 테마 요약 섹션 포함(P23), 기존 항목은 원본 기록으로 독립 계산. 일일 리포트는 P24로 병행. 재생성은 새 판 추가·최신본 기본 표시·이전본 열람 가능, 학부모 리포트당 1회·관리자 무제한. 분석 대화 기본 기간 최근 7일(오늘 포함). 다운로드 PDF·Markdown |
| P07 | 관리자 권한 | 학생 원문은 서비스 운영 권한이 신고·문의 연결 시도만 열람(감사 기록). 미션 검토·게시는 콘텐츠 권한 1인 가능(작성자 포함). 검토 요청은 별도 요청으로 전환. 게시 중 수정본은 재검토·재게시 후 신규 시도부터 적용, 진행 중 시도는 시작 당시 버전 유지. 작업 재처리는 서비스 운영 권한 전원 |
| P08 | 수치 집계 | 대상: 기간 내 답변 제출 1건 이상인 시도(완료·미완료, 완료 여부 별도 표시). 제외: 처리 실패만 있는 시도·삭제 기록. 분모 5 미만은 비율 대신 개수만. 전후 변화는 시도당 최초 vs 마지막 답변: 글자 수(공백 포함)·문장 수(`.` `?` `!`·줄바꿈 기준 비지 않은 덩어리)·까닭을 잇는 말(고정 목록 `왜냐하면`·`때문`·`그래서`·`따라서` 각각의 문자열 매칭 횟수 합계, #51 담당자 확인 2026-10-27). 도움 없이 시작한 비율 = 최초 답변 전 도움 열람 없는 시도 / 집계 대상 시도 |

- 국어 우선(P15): 초5·6 미션은 유형마다 위 성취기준과 입력을 기본으로 한다. 문제 해결하기를 뺀 네 유형은 입력 형식상 M2 대상(초5·6 서술·논술)이며, 실제 적용은 평가 기준을 통과한 범위만이다(FN-JDG-05)
- 문제 해결하기(국어 우선의 예외): 평가 요소(문제 정의·방법·결과 확인)가 수학 풀이 틀(무엇을 구하나요·어떻게 구할까요·계산·확인해 보기)과 맞고, 따져 보기(주장·근거·다른 관점)와 구분되며, 최종 답은 정답 키 규칙으로 모델 없이 판정할 수 있어 수학을 기본으로 둔다. 최종 답은 정답 키 규칙(FN-JDG-02), 풀이 단계는 LLM 근거 대조로 판정하며 M1 교차 확인은 후순위다(FN-JDG-04 미검증 M1 과정 보류 유지). 국어 서술형 문제 해결 미션(`[6국02-04]` 문제 상황과 관련된 다양한 관점의 글을 읽고 이를 문제 해결에 활용한다.)은 보조이며 평가 기준을 통과한 범위에서 M2를 적용할 수 있다(FN-JDG-05)
- 다른 과목: 국어를 먼저 완성한 뒤 확장한다(문제 해결하기의 수학 풀이는 위 예외). 확장 시 같은 유형·평가 요소에 해당 교과 성취기준을 연결한다. M2 서술 학습 데이터 AI Hub 71818에 사회·과학·수학 서술형도 있어 확장 시 M2 적용 범위를 다시 평가한다
- 초3·4: M2는 쓰지 않는다(서술 학습 데이터 71818은 초5~중3, 논술 틀은 초5~6만 제공 P03). 과목·성취기준은 미션 작성 시 고시 원문으로 확인해 정한다
- 학년 확장: 기획서 대상은 초1~중3이며 고등학교 논술은 추후 확장이다. 이 절은 P03 지원 학년(초3~6) 기준이고, 초1~2·중학교는 확장 시 같은 유형·평가 요소에 해당 학년군 성취기준을 연결한다. 논술 545 데이터가 초4~고3을 포함하므로(기획서 6장) 중·고 논술 확장 시 M2 논술 적용 범위를 다시 평가한다
- 판정: 유형별 요소를 미션의 연결 성취기준의 성취수준 문장에 맞춰 2~3개로 구체화하고(기획서 5.3(2), 성취기준·성취수준 연결은 아래 #336), 요소별 있음/없음과 근거 구절로 판정한다(FN-JDG-03). VALUE 루브릭의 4단계 점수는 쓰지 않는다(기획서 5.3(2)). 생각 유형 판정은 이 요소 판정으로 한다(FN-JDG-03, 기획서 5.3(2)). M2 항목 점수는 "AI 관찰"로 구분하며(FN-JDG-05), 유형 평가와 M2 점수를 잇는 기준은 정하지 않았다([기획 결정](../report/planning-decisions.md#2-국어m2-우선과-생각-유형-매핑-213) 2.4)
- 성취기준 문장에 직접 없는 평가 요소(분석하기 ①②, 새로 만들기 ①③)는 미션 질문과 기준표 요소에서 요구한다
- 검증: 유형별 대표 미션 1개씩 총 5개 미션의 답안 100개(미션당 20개)를 사람 2명이 독립 표시해 사람-사람·사람-LLM 일치도를 비교하고, 기준 미달 유형·미션은 판정하지 않고 기록만 한다(기획서 5.3(5)). NFR-AIQ-01은 LLM 판정 대상 미션마다 예시 답안 20개로 범위가 달라 [기획 결정](../report/planning-decisions.md#2-국어m2-우선과-생각-유형-매핑-213) 2.4에 확인 필요로 둔다
- 한계: 다섯 유형 묶음은 팀이 구성한 틀이며 표준이라고 주장하지 않는다. VALUE 루브릭은 대학생용이라 성취기준 연결과 일치도 검증으로만 뒷받침한다
- 성취기준 문장은 교육부 고시 제2022-33호 국어과·수학과 기준이며, 이를 인용한 경기도교육청 「2026학년도 초등학교 5~6학년 1~2학기 수업-평가 계획 예시 자료」와 문구를 대조했다(2026-11-02). 현재 데모 시드의 성취기준은 [learning 보고서](../report/learning.md) 1장을 따른다

- 필수 요소인지 들어가면 좋은 생각(`good_thought`)인지는 코드가 아니라 미션 요소마다 정한다
- 입력 방식: 고르기·순서·분류는 규칙 판정이라 생각 요소를 판정하지 않으므로 `ANSWER_KEY` 요소 하나만 둔다. `FINAL_ANSWER`는 풀이 단계에만 둔다(기존)
- 따져 보기 논술 미션은 `EVALUATE_CLAIM`·`EVALUATE_EVIDENCE`·`EVALUATE_PERSPECTIVE`를 모두 둔다(기획서 5.3(3) 논증 요소 충족률)
- 검사: 기준표 저장 때 code 모양(표준 코드·`e`+숫자·예약 코드)을 확인하고, 미션 유형·입력 방식에 맞는지는 게시 때 확인한다(FN-ADM-10·11). 미션 내용과 기준표를 따로 저장하므로 저장 때는 미션 유형을 알 수 없다
- 기획서 5.3과 다른 점(#262): 돌아보기 요소를 ① 자기 생각 과정 ② 바뀐 점에서 위 세 요소로 바꾸고, 처음 답 충족률·되묻기 후 보완률의 분모를 필수 요소만으로 한다(FN-RPT-05, 들어가면 좋은 생각은 정답 조건이 아님). 분석하기는 기획서 2요소 그대로다(블룸 개정 분류에서 분류·비교는 "이해" 단계). FAC-09 "같은 기준표"는 유형별 평가 요소로 보아 기획서 5.3(4) "같은 유형·학년군 미션끼리"와 같은 뜻으로 해석한다
- 표준 코드 선택 근거(VALUE 루브릭·블룸 분류·성취기준)와 시드 20문항 대조는 [learning 보고서](../report/learning.md) #262 절

#### 성취기준·성취수준 연결 (#336 설계, #353 구현)

미션은 성취기준 표에서 고른 성취기준 코드 1개 이상과, 성취기준마다 고른 성취수준 단계에 연결한다(기획서 5.3·6.2 ①, FAD-03·08). 표 조회와 LLM 초안 흐름은 FN-ADM-20·21, 저장 구조는 [ERD](erd.md) 4.1.1. learning 표·저장·검사·초안 작업은 #353, ai 초안 생성은 #354, core 프록시는 #355, 관리자 화면은 #356이다.

- 성취기준 표: 2022 개정 교육과정 초1~중3 765개. 코드는 대괄호 없이 저장한다(`6국01-02`, 지금 `mission_version.achievement_standards` 시드와 같음). 2026.1 일부개정 25개(통합교과, 2028년 적용, 초1~2)는 넣지 않는다. 그중 12개 코드가 현행과 코드는 같고 문장이 달라 코드로 찾을 수 없고, 지원 학년(P03)에도 해당하지 않는다(FAD-08 "790개"와 다름, [기획 결정](../report/planning-decisions.md#25-기획서요구사항-정의서-반영-목록) 2.5)
- 성취수준 문장: 평가원 자료의 이용 조건을 확인하기 전까지 넣지 않는다(저장소가 공개, 수집데이터 보고서 "성취기준 문서: 이용 조건 확인 후 사용"). 그동안 단계 수(초 3단계 A~C, 중 5단계 A~E)만 넣고, 판정 요소·초안은 성취기준 문장으로 구체화한다
- 성취수준 단계: 미션 작성·초안 요청 때 성취기준마다 관리자가 고른다(학년별 목표 단계는 정하지 않음). 기존 성취기준 코드 목록은 그대로 두고 단계를 따로 저장한다(웹·OpenAPI의 코드 배열 계약 유지)
- 요소와 성취기준: 기준표 요소마다 그 요소를 구체화한 성취기준(`standardCode`, 선택)을 남긴다. 정답 요소(`ANSWER_KEY`·`FINAL_ANSWER`)와 #336 전 요소는 비운다. 판정 방식(FN-JDG-03)은 바뀌지 않는다
- 행동: 요구사항 FAD-03·05·08의 "행동"은 성취기준 문장의 동사다(기획서 6.2 ④ "행동(성취기준 동사)"). 문장 안에 있으므로 칸을 따로 두지 않고 검토 때 학년·내용·행동이 미션과 맞는지 확인한다(FN-ADM-11). 성취기준 표의 "생각 유형 후보(자동)"는 동사 낱말 규칙으로 채운 값이라 넣지 않고 유형은 관리자가 고른다
- 데모 시드 20문항: 생성 방식 `MANUAL`, 성취수준 단계와 요소 `standardCode`는 비우고 APM 검수 때 채운다

#72의 대화형 리포트 방향에 따라, 학부모 대화에서 설정 변경안을 만들고 확인 후 저장한다. 허용 항목은 섹션 순서, 기존 집계 지표 강조, 기본·쉬운 설명·간결한 서술 톤이다. 기본 정보와 수치는 유지하며 계산식·판정 기준을 변경하지 않는다. 섹션 자체 숨김을 허용받은 것으로 해석하지 않는다.

학부모 `기록에 물어보기` 화면에서 기존 대화 또는 새 설정 대화를 사용한다. 자연어 요청 후 현재 설정과 변경안을 비교하고 명시적으로 확인한 경우만 저장한다. 취소·입력 수정·대화 이동은 미확정 변경안을 폐기하고, 만료·실패 시 저장 성공으로 표시하지 않는다. 원문 공개를 강제로 켜는 기능은 제공하지 않는다.
