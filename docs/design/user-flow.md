# 사용자 흐름도

- 근거: [유스케이스](usecase.md), [기능명세서 1.4 확정 정책](functional-spec.md#14-확정-정책), [시퀀스 다이어그램](sequence-diagram.md), [상태 다이어그램](state-diagram.md), [화면설계서 v2.1](../screen-design/README.md)(`docs/screen-design/2026-10-29-v2.0/screens.json`), 웹 라우트(`frontend/web/src/presentation/router.tsx`·각 Workspace 메뉴)
- 범위: 학생·학부모·관리자가 화면에서 겪는 이동 순서와 분기. 서비스 간 호출은 시퀀스 다이어그램, 상태값 전이 조건은 상태 다이어그램
- 미션 한 번 안의 판정·되묻기 분기는 [유스케이스 4.1](usecase.md#41-미션-한-번의-흐름)을 따르고 여기서는 화면 단위로만 표시
- `(P04)` 형태는 확정 정책 번호

## 1. 공통 규칙

| 항목 | 규칙 |
|---|---|
| 화면 노드 | `["SC-xx-xxx 화면명<br/>URL"]`, 화면 ID는 화면설계서 v2.1 기준 |
| 판단 노드 | `{"..."}` 사용자 선택 또는 서버 응답에 따른 분기 |
| 시스템 처리 | `("...")` 사용자 화면 밖에서 일어나는 처리 (OAuth·판정·리포트 생성 등) |
| 역할 부여 | URL 입력만으로 역할을 주지 않음. 로그인 응답의 `role`·`startPath`·`nextAction`, 학생 세션으로만 진입 |
| 메뉴 노출 | 학부모·학생은 역할 고정 메뉴, 관리자는 승인 권한(`CONTENT`·`SERVICE_OPS`·`PAYMENT_VIEW`·`PAYMENT_REFUND`)별 메뉴 |
| 목업 화면 | SC-01-001·SC-01-002의 이메일·비밀번호 폼은 개발 목업. 운영 모드는 Google 인증 또는 아이디·비밀번호(#415, `/login`의 "또는 아이디로 로그인", `/signup`의 아이디 가입 폼)로 시작하고 이용 동의는 `/parent/onboarding`에서 진행 |
| 학부모 로그인 수단 | Google과 아이디·비밀번호는 서로 연결되지 않음(한 계정은 한 가지 수단). 중요 작업의 본인 재확인은 Google 계정은 Google 새 탭, 아이디 계정은 로그인 비밀번호 입력 (#415) |
| 관리자 주소 | 사용자 화면(`/login`·도움말 등)에 `/admin/login` 링크·관리자 문구 없음. 관리자는 주소를 직접 입력하고, 등록된 ID·비밀번호 또는 Google로 로그인 (#369) |

- 분석 대화·리포트 답변 화면에서 바로 오류 신고 가능 (`targetType` ANALYSIS·REPORT). 학생은 커뮤니티 공유물도 신고 (`COMMUNITY_POST`)
- 학생이 공개 설정을 끈 동안 원문·근거·원문 인용은 보이지 않고 수치만 표시 (#206)
- 자녀 이관(#289)은 탈퇴 전 보호자를 바꾸는 정식 절차다. 받는 학부모가 수락하기 전에는 연결·기록 접근이 바뀌지 않으며, 수락 후 학생 기기는 새 학부모가 다시 등록한다. 서버·웹 기능 플래그로 신규 대상 조회·요청·수락을 켠다(기본 꺼짐). `/parent/transfers`의 본인 목록·취소·거절은 기능 off·동의 누락에도 유지한다(#307). 동의 화면에서도 이관·계정 관리로 이동할 수 있으며 취소 후 탈퇴는 별도 재인증·최종 확인을 거친다
- 동석 진입으로 학생 화면을 쓰는 동안 학부모 세션은 잠긴다. 학생 로그아웃 후 로그인 화면의 "학부모 화면으로 돌아가기"(`ParentUnlock`)에서 보호자 비밀번호로 복귀한다. 보호자 비밀번호는 자녀 기기·PIN 화면에서 본인 재확인 후 설정한다
- 본인 재확인(#45·#415): Google 계정은 Google 새 탭에서 재인증하고, 아이디·비밀번호 계정은 같은 화면에서 로그인 비밀번호를 다시 입력한다(5회 실패 시 로그인과 함께 15분 잠금). 이관을 받는 학부모는 Google 이메일로 조회하므로 아이디 계정은 받는 쪽이 될 수 없다
- 무료 자녀는 분석 대화 진입 시 프리미엄 안내만 표시, 주간 리포트는 수치만 표시 (P13). 일일 리포트는 무료·프리미엄 동일, 리포트 대화는 프리미엄 전용 (P24·P25)
- 커뮤니티 보호자 선택 동의는 정보 관리(SC-03-009)에서 자녀별 저장·철회. 학부모는 자녀 공유물·받은 반응·포인트만 보고 다른 학생 풀이는 볼 수 없음

- 화면 이탈·새로고침 시 초안 자동 저장본으로 복원 (UC-12)

- 학생은 알림 메뉴 없음 (고객센터 메뉴에 미포함)
- 학습 완료 시 포인트 적립, 커뮤니티 공개를 켠 학생은 미션을 처음 마무리한 시도의 마지막 답변이 자동 공유됨(다시 풀기는 공유 안 함) (P20~P23). 커뮤니티는 같은 미션을 마무리해야 열림(큰 질문 정답 고르기 문제는 엔딩을 본 뒤). 2026-11-10 개정(#483): 테마 문제는 월~금 KST 00:00에 하나씩 공개되어 쌓이고 그 주 토요일까지 언제든 시작(진행 중 시도는 자정 후에도 이어하기), 일요일은 닫힘(프리미엄은 토요일과 같이 이용). 무료는 테마 문제 주 5개(하루 상한 없음), 생각 유형별 미션 고르기는 프리미엄 추가 문제. 아이 화면에는 결제 유도 문구를 넣지 않음(구매 안내는 보호자 화면). 꾸미기는 `lake`·`mungchi` 외 포인트 해금, 캐릭터 아이템 4슬롯

## 7. 확인 필요 가정

- 학부모 구독 결제·구독 관리(UC-17·UC-18, #184): `/parent/billing`(이용권·결제)에서 상품 선택 → 토스 결제위젯 결제 → `/payment/success`·`/payment/fail` 결과 확인, 같은 화면의 구독 관리에서 자동결제 수단 등록(`/payment/billing/success`·`/payment/billing/fail`)·자동 갱신 해지·철회·환불 요청. 테스트 키 환경만 사용(P14). 단계별 화면 흐름도는 미반영
- 이용 동의 화면(`/parent/onboarding`)과 관리자 메뉴 큐·DLQ(`/admin/queues`)는 화면설계서 v2.1에 별도 화면 ID 없음
- 2026-11-06 결정 화면(UC-29~34, #393~#395 구현): 이번 주 테마·되돌아보기·커뮤니티·자녀 커뮤니티·일일 리포트 상세·관리자 주간 테마·꾸미기 아이템은 화면설계서 v2.1에 없어 화면 ID 없이 이름·URL로 표시. URL은 웹 구현 기준(주간 테마·되돌아보기는 별도 페이지 없이 학생 홈 카드, 자녀 공유물·포인트는 학부모 대시보드 아래), 화면 ID는 화면설계서 개정 때 부여

- #427 기존 `/parent/account` 주소는 자녀·기간 조건을 보존해 계정 관리 탭으로 연결한다. 이용 동의 전에도 이 탭의 탈퇴 절차는 접근할 수 있다. #426~#429 웹 기준은 [학부모 화면 사용성 기준](frontend-usability.md)을 따른다.

### 2026-11-10 학부모 동선 통합

- `/parent/report`: 리포트 보기와 AI 질문을 한 메뉴로 통합. 리포트 상세에서 질문하기를 누르면 같은 챗봇에 자녀·기간을 연결한다. 일일은 기존 reportId 고정 대화, 주간은 기존 기간 범위 대화를 사용한다. `/parent/analysis` 주소는 자녀·기간을 보존해 질문 화면으로 연결한다.
- 자녀 추가 등록은 계정·자녀 설정 → 프로필, PIN은 기기·PIN → 자녀 알약 선택 → PIN 입력·저장. PIN 저장은 로그인된 보호자의 현재 자녀 권한으로 처리하고 추가 Google/비밀번호 재인증은 제거한다. 보호자 비밀번호·삭제·탈퇴는 기존 재인증을 유지한다.
- 사고뭉치 로고는 역할별 홈으로, 상단 맨 오른쪽 종은 알림 목록·수신 설정 창으로 연결한다. 학생에게 보호자 알림을 노출하지 않는다.
- 리포트에서 질문한 검증 완료 답변은 해당 판의 실제 지표·문제·원문 인용 위치를 초록 테두리와 문구로 표시한다. 답변별 ‘리포트 근거 위치 보기’로 이동하며 새 질문·자녀/기간·공개 설정 변경 시 이전 강조를 지운다. 현재 원문 접근 권한은 기존 메시지 근거 API로 다시 확인한다.
