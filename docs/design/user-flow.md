# 사용자 흐름도

- 근거: [유스케이스](usecase.md), [기능명세서 1.4 확정 정책](functional-spec.md#14-확정-정책), [시퀀스 다이어그램](sequence-diagram.md), [상태 다이어그램](state-diagram.md), [화면설계서 v2.1](../screen-design/README.md)(`docs/screen-design/2026-10-29-v2.0/screens.json`), 웹 라우트(`frontend/web/src/presentation/router.tsx`·각 Workspace 메뉴)
- 범위: 학생·학부모·관리자가 화면에서 겪는 이동 순서와 분기. 서비스 간 호출은 시퀀스 다이어그램, 상태값 전이 조건은 상태 다이어그램
- 미션 한 번 안의 판정·되묻기 분기는 [유스케이스 4.1](usecase.md#41-미션-한-번의-흐름)을 따르고 여기서는 화면 단위로만 표시
- `(P04)` 형태는 확정 정책 번호

## 1. 공통 규칙

| 항목 | 규칙 |
|---|---|
| 화면 노드 | `["SC-xx-xxx 화면명<br/>URL"]`, 화면 ID는 화면설계서 v2.1 기준 |
| 판단 노드 | `{"..."}` 사용자 선택 또는 서버 응답에 따른 분기 |
| 시스템 처리 | `("...")` 사용자 화면 밖에서 일어나는 처리 (OAuth·판정·리포트 생성 등) |
| 역할 부여 | URL 입력만으로 역할을 주지 않음. 로그인 응답의 `role`·`startPath`·`nextAction`, 학생 세션으로만 진입 |
| 메뉴 노출 | 학부모·학생은 역할 고정 메뉴, 관리자는 승인 권한(`CONTENT`·`SERVICE_OPS`·`PAYMENT_VIEW`·`PAYMENT_REFUND`)별 메뉴 |
| 목업 화면 | SC-01-001·SC-01-002의 이메일·비밀번호 폼은 개발 목업. 운영 모드는 Google 인증 또는 아이디·비밀번호(#415, `/login`의 "또는 아이디로 로그인", `/signup`의 아이디 가입 폼)로 시작하고 이용 동의는 `/parent/onboarding`에서 진행 |
| 학부모 로그인 수단 | Google과 아이디·비밀번호는 서로 연결되지 않음(한 계정은 한 가지 수단). 중요 작업의 본인 재확인은 Google 계정은 Google 새 탭, 아이디 계정은 로그인 비밀번호 입력 (#415) |
| 공개 루트·로그인 진입 | `/`는 로그인 없이 서비스 소개와 학생·학부모·관리자 로그인, 학부모 가입 진입을 제공한다(#724). 선택 시 해당 탭의 이전 인증·조회 캐시를 비우고 선택한 로그인 화면을 연다. 기존 기기 등록·쿠키·다른 탭의 세션은 유지하며, URL 선택만으로 역할을 부여하지 않는다. |
| 관리자 주소 | 공개 루트의 관리자 로그인 링크 또는 `/admin/login` 직접 입력으로 진입한다(#724). 등록된 ID·비밀번호 또는 Google 인증과 기존 관리자 권한 검사를 유지한다(#369). 일반 `/login`·도움말에는 관리자 링크를 추가하지 않는다. |

- 분석 대화·리포트 답변 화면에서 바로 오류 신고 가능 (`targetType` ANALYSIS·REPORT). 학생은 커뮤니티 공유물도 신고 (`COMMUNITY_POST`)
- 학생이 공개 설정을 끈 동안 원문·근거·원문 인용은 보이지 않고 수치만 표시 (#206)
- 자녀 이관(#289)은 탈퇴 전 보호자를 바꾸는 정식 절차다. 받는 학부모가 수락하기 전에는 연결·기록 접근이 바뀌지 않으며, 수락 후 학생 기기는 새 학부모가 다시 등록한다. 서버·웹 기능 플래그로 신규 대상 조회·요청·수락을 켠다(기본 꺼짐). `/parent/transfers`의 본인 목록·취소·거절은 기능 off·동의 누락에도 유지한다(#307). 동의 화면에서도 이관·계정 관리로 이동할 수 있으며 취소 후 탈퇴는 별도 재인증·최종 확인을 거친다
- 동석 진입으로 학생 화면을 쓰는 동안 학부모 세션은 잠긴다. 학생 로그아웃 후 로그인 화면의 "학부모 화면으로 돌아가기"(`ParentUnlock`)에서 보호자 비밀번호로 복귀한다. 보호자 비밀번호는 자녀 기기·PIN 화면에서 본인 재확인 후 설정한다
- 본인 재확인(#45·#415): Google 계정은 Google 새 탭에서 재인증하고, 아이디·비밀번호 계정은 같은 화면에서 로그인 비밀번호를 다시 입력한다(5회 실패 시 로그인과 함께 15분 잠금). 이관을 받는 학부모는 Google 이메일로 조회하므로 아이디 계정은 받는 쪽이 될 수 없다
- 무료 자녀는 분석 대화 진입 시 프리미엄 안내만 표시, 주간 리포트는 수치만 표시 (P13). 일일 리포트는 무료·프리미엄 동일, 리포트 대화는 프리미엄 전용 (P24·P25)
- 커뮤니티 보호자 선택 동의는 정보 관리(SC-03-009)에서 자녀별 저장·철회. 학부모는 자녀 공유물·받은 반응·포인트만 보고 다른 학생 풀이는 볼 수 없음

문장 없이 보기를 바로 보여 주고 뭉치는 "골라 봐·눌러 봐"로 할 일을 말한다. 시작 이야기 끝 버튼 문구("이번 주 시작하기 · 오늘 문제로 →")는 그대로. **미션 완료 화면**(확정 시안 SC-02-012 돌아보기의 '미션 완료!', 예전 웹은 돌아보기 저장 뒤 바로 내 공책으로 가 이 화면이 빠져 있었음): 돌아보기를 저장하면 문제 화면 위에 카드(동행 캐릭터·"미션 완료!"·"미션 학습 완료"·"이번 답은 내 공책에 남았어요")를 띄운다. 테마 문제는 주간 테마를 다시 받아 엔딩이 됐으면 이야기의 끝으로, 아니면 처음 마친 요일의 단서(`days[].clue`)를 "○요일 단서가 열렸어요!"(금요일은 "마지막 단서가 열렸어요!")로 보여 주고 단서 모음(금요일은 정답 고르기)으로 잇는다. 다시 풀기·더 풀어 보기는 단서 칸 없이. 아래에 내 공책 보기·같은 미션 친구 생각 보기(`/student/community?mission=`, 엔딩 전 금요일 문제는 숨김)·홈으로. 시안의 "+10 포인트"는 넣지 않는다(미션마다 처음 한 번이라 다시 풀기는 0이고, 화면이 실제로 쌓인 값을 알 수 없음). 시안: 설계 캔버스 `TodaySceneTalk`·`MissionWriteTalk`·`Reflect` 보드

- 장면별 부분 다시 생성(#537): 상세의 시작·종료 칸(영상·그림)과 요일 칸(그림·미션)에 다시 만들기 버튼을 두고 서버가 준 `regenerableTargets`에 있는 대상만 보인다. 누른 칸에서 같이 바뀌는 범위를 확인받고 그 대상만 다시 만든 새 초안을 연다(원래 초안은 그대로). 부분 결과 초안은 상세에 다시 만든 대상과 원래 초안 링크, 목록 출처에 '부분'을 보인다. 생성 중·채택 초안에는 버튼이 없다.

### 4.1 주간 테마 한 주 시나리오 (#483)

바뀐 규칙([기능명세 P23·P21·P13](functional-spec.md#14-확정-정책))으로 본 학생 네 유형의 한 주. 큰 질문 정답 고르기는 금요일 문제를 마무리한 뒤 한 주에 한 번이다(learning #484, 틀리면 토요일 금요일 문제 다시 풀기를 마친 뒤 엔딩). 포인트는 테마 관련만 셈(문제 완료 10·당일 풀이 5·개근 30·주간 완주 10, 되돌아보기 열람 10은 별도). 구현은 learning #484·core #485·report #486·web #487.

| 학생 | 월~금 | 토요일 | 일요일 | 엔딩 | 테마 포인트 |
|---|---|---|---|---|---|

- 장면 움직임(#440, ai 움직임 형식 v1): 시작·종료 이야기는 영상이나 그림 + 움직임(카메라·컷 문구)이 있으면 화면 가득 먼저 재생하고, 끝나거나 '건너뛰기'를 누르면 이야기 화면(그림은 멈춤, '다시 보기'로 다시 재생). 문제 화면 장면 그림 위에는 효과(effects)만 재생하고 살펴보기 지점(spots)은 학생 화면에 넣지 않음(사용자 결정 2026-11-13, 오늘 장면에도 넣지 않음 #807). 오늘 장면 그림은 효과와 처음 3초 살짝 당겨졌다 돌아오는 연출(확정 시안 Main)만 쓰고, ai 움직임의 카메라 이동(`camera`)은 쓰지 않음(말꼬리가 가리키는 화자 위치가 어긋나지 않게, #807). 기기 '동작 줄이기'나 문제 화면 '움직임 줄이기'면 재생하지 않음(이야기는 화면 가득 재생 없이 바로 이야기 화면). 그림이 없는 테마와 그림을 못 불러온 경우는 이야기 글만, 문제 장면은 같은 자리에 '그림을 불러오지 못했어요'
- 일요일 하루 이용권 단건 결제는 #430 PG 결정 뒤 후속

## 8. 학부모 화면 사용성 기준 (#426~#429)

- 기존 `achromatic-ledger` 방향(seed `683525200`)과 사고뭉치 로고·글꼴을 유지한다. 탐색은 중립색, 강조색은 주요 행동과 상태에 쓴다.
- 기본·보조 버튼은 테두리와 배경으로 링크와 구분하고 누르는 영역은 최소 44px로 한다. 본문·버튼 문구는 읽을 수 있는 크기를 유지한다.
- 학습 현황은 활동 수치, 리포트는 생성된 문서, AI 챗봇은 기간을 선택한 질문에 답한다. 날짜 필터는 기록·대화에만 둔다.
- `/parent/settings`의 프로필·공개/동의·계정 관리 탭을 유일한 설정 화면으로 사용한다. 예전 `/parent/account`는 기존 자녀·조회 조건을 보존해 계정 관리 탭으로 보낸다. 이용 동의 전에도 계정 관리·탈퇴 진입은 유지한다.
- 원문 비공개일 때 원문 조회·질문·다운로드를 요청하지 않고 이유와 사용할 수 있는 기능을 안내한다. 공개 권한은 자녀가 결정한다.
- 오류는 사용자 안내와 가능한 재시도를 먼저 보여 준다. 오류 코드·확인 번호·상세 응답은 접힌 자세히 영역에 둔다.
- 신규 결제는 상품·가격·1개월 기간·자녀 수·기능 확인 → 자녀 선택 → 첫 달 결제 → 별도 자동결제 등록 순서다. 자동결제가 기본 등록된 것처럼 안내하지 않는다.
- 상품이 없으면 구매 폼과 빈 주문 요약을 숨긴다. 설정 장애·비활성 버튼은 사용자에게 사유와 문의 경로를 제공하며 키 값은 표시하지 않는다.
- 상태는 한글로, 자녀는 별명으로 표시한다. 주문번호는 접힌 거래 상세에 둔다. 모바일에서 본문 가로 넘침이 없어야 한다.
- 1440·768·390px에서 기본·비공개·빈 목록·실패 상태와 설정 경로를 확인한다. 가상 결제 검사와 실제 PG 검증은 구분한다.

### 8.1 리포트·챗봇·알림·PIN 동선 통합 (#462)

#462 점검 범위는 아래 리포트·챗봇·로고·알림·자녀·PIN 동선과 기존 설정·원문 비공개·결제 사용성 기준이다. 구체적인 추가 요구사항이 올라오면 해당 내용과 대조한다.

- 학부모 리포트와 AI 챗봇은 `/parent/report` 한 메뉴 안에서 리포트 보기·질문하기로 이동한다. 선택한 리포트의 자녀·기간을 같은 챗봇에 연결하며, 일일 리포트의 고정 범위·최신판 계약과 원문 공개/이용권 권한을 유지한다. `/parent/analysis`는 기간을 보존해 질문 화면으로 연결한다.
- 사고뭉치 로고는 로그인 역할에 맞는 홈으로 연결한다. 자녀 추가 등록은 계정·자녀 설정의 프로필에서 한다.
- 알림은 상단 우측 끝의 종 버튼으로 연다. 같은 알림 창에서 목록·읽음 처리·수신 설정을 이용한다. 학생은 보호자 알림에 접근하지 않는다.
- 자녀 PIN은 선택한 자녀 한 명의 폼만 표시한다. 자녀 선택은 줄바꿈 가능한 알약 버튼과 키보드 이동을 제공한다. PIN 저장에는 추가 재인증이 없고, 서버의 활성 보호자 세션·현재 자녀 권한·PIN 규칙·잠금 해제·감사는 유지한다. 보호자 비밀번호·삭제·탈퇴의 재인증은 별개다.
- 기존 `achromatic-ledger` 배치·사고뭉치 로고·글꼴을 이어 사용한다. 이번 화면의 주 작업은 리포트에서 질문으로 이어지는 흐름이며, 임의 생성 자료나 새 시각 스타일은 추가하지 않는다.

### 8.2 답변과 리포트 근거 위치

- 리포트에서 질문할 때 같은 리포트와 답변을 함께 표시한다. 검증 완료 답변의 수치 정의·원문 식별자로 연결되는 항목만 초록색 경계선과 ‘선택한 답변의 근거’ 문구로 강조한다. 색만으로 의미를 전달하지 않는다.
- 자녀·리포트·판·기간이 일치해야 한다. 일일 리포트는 대화가 서버에서 고정한 실제 판을 사용하며, 주간은 질문을 시작한 리포트 판과 기간을 사용한다. 실패·생성 중·새 질문·다른 답변·다른 자녀/기간·공개 철회 때 이전 강조를 제거한다.
- 원문 연결은 기존 메시지 근거 API로 현재 접근 가능 여부를 확인한다. 삭제/비공개/조회 실패 또는 연결 정보가 없는 항목은 추측하지 않는다. 리포트와 learning의 알려진 집계 지표는 정의와 기간·분자·분모가 일치할 때만 연결하며, 같은 숫자나 답변 키워드만으로 강조하지 않는다.
- 데스크톱은 답변과 리포트를 나란히 놓고 리포트 안에서 근거 위치로 이동한다. 태블릿·모바일은 대화 뒤에 리포트를 놓으며, 답변의 ‘리포트 근거 위치 보기’로 해당 항목에 이동·초점을 준다. 동작 줄이기 설정을 따른다.
- 연결 항목이 없으면 이유를 안내한다. 서술 요약·테마 제목처럼 원문 식별자가 없는 영역이나 집계 기준이 다른 완료 지표는 임의로 연결하지 않는다. 새 API·모델 응답 필드는 추가하지 않는다.


### 8.3 학부모 공통 화면 개선 (#548)

- 테마색 #277044를 셸·사이드바 배경에 사용하고, 본문·상단 바는 #f3f7f4 바탕과 진한 글자로 구분한다.
- 상단 바는 y=0에 고정된 둥근 카드다. 로고·자녀 선택·알림·로그아웃을 배치하며 “학부모 공간” 문구와 직접 학습 시작 버튼은 제공하지 않는다. 상단 개발 목업 안내 줄은 표시하지 않는다(연결 모드는 유지).
- 본문 폭은 상단 바의 모서리 곡률 안쪽 평평한 구간에 맞춘다. 상단 바 바깥 여백은 투명하게 두며 배경 마스크로 본문을 가리지 않는다.
- 사이드바는 폭을 줄이고 상단 바 아래에 배치한다. 자녀 이용권 정보와 자체 스크롤은 제거한다. 낮은 창에서는 일반 페이지 흐름, 작은 화면에서는 메뉴 대화상자로 모든 메뉴에 접근한다.
- 도움말·문의·공지·처리 결과도 같은 학부모 셸에서 표시하며 선택 자녀·기간을 유지한다.
- 공개·동의 이력은 응답의 document.content(당시 버전)를 펼쳐 표시한다. 본문이 없으면 최신 문서를 대신 표시하지 않고 부재를 안내한다.
- 무료 플랜을 표시한다. 유료 구독의 무료 전환은 현재 기간을 유지하는 기존 자동 갱신 해지 확인으로 연결하며 즉시 환불·권한 회수는 하지 않는다.
- 결제수단 선택은 별도 탭에서 기존 API·멱등 키로 주문을 생성한다. 완료·취소·실패는 기존 콜백을 따르며, 원래 탭 복귀 시 구독/거래 상태를 갱신한다. 팝업 차단은 안내 후 재시도한다.
- 리포트 하단 버튼, 알림 필터·쪽수, 닫기 아이콘의 크기·중심선을 통일한다. 드롭다운 화살표는 오른쪽 여백을 두고 지원 브라우저에서는 둥근 메뉴·테마색 선택 항목을 사용한다. 미지원 브라우저와 강제 색상 모드는 시스템 메뉴를 유지한다.

### 8.4 관리자 테마 통일

- 학부모 대시보드와 같은 #277044 사이드바·주요 버튼, #f3f7f4 본문·상단 바, 흰 카드와 #192b21 본문 글자를 사용한다.
- 선택 메뉴는 흰 바탕·진한 녹색 글자로 구분하고 키보드 초점, 선택 탭·행, 차트에도 같은 팔레트를 적용한다. 관리자 로그인도 동일한 배경과 버튼색을 사용한다.
- 관리자 메뉴 구조·권한·업무 상태·반응형 배치는 유지한다.
- 관리자 드롭다운에도 학부모와 같은 화살표 오른쪽 14px 여백, 둥근 메뉴·항목, 녹색 선택 배경을 적용한다. 미지원 브라우저·강제 색상 모드는 기본 선택 메뉴를 유지한다.
- 관리자 가독성: 본문 15px, 제목 26px·구역 제목 18px, 입력·버튼 글자 14px를 사용한다. 보조 글자 대비·라벨 굵기와 입력 경계를 강화하고 주요 조작 영역은 40px 이상으로 둔다. 오류 안내는 붉은 바탕·테두리·글자로 구분한다.
- 비교 카드의 완료 상태는 테마색 #277044 배경·흰 글자로 구분한다. 운영 요약의 학습 완료와 작업 처리 완료 카드에 적용하며 집계가 0이어도 상태별 구분은 유지한다.
- 관리자 공통 작업 버튼은 테마 녹색·흰 글자로 통일한다. 종료·게시/판매 중단·삭제·버리기·반려 작업은 빨간색으로 구분하고, 비활성 버튼은 회색을 유지한다. 상태 배지는 흰 배경에 녹색 글자·외곽선, 종료·판매 중단 배지는 빨간 글자·외곽선으로 표시한다. 본문 패널·입력란·미선택 탭은 흰색이다.
- 문의·공지 패널은 나란히 같은 높이로 배치하고 하단 페이지 이동 버튼·쪽수의 중심선과 패널 하단을 맞춘다. 행의 관리 버튼 사이에도 간격을 둔다. 좁은 화면에서는 패널을 세로 배치하고 표는 내부에서 스크롤한다.

### 8.5 학생·학부모 접근성 보완 (#639·#640·#641)

- 역할 인증 틀은 일반 컨테이너로 두고 각 화면의 본문 main을 최상위 랜드마크로 유지한다. 본문 안 공개 상태 안내는 region으로 구분한다. 미션 풀이의 로딩·오류·작성 상태 모두 main 하나를 제공한다.
- 풀이 진입 시 제목으로 초점을 이동한다. 답 제출 성공 후 결과 안내에 초점을 한 번 이동하고 피드백 갱신·자동 저장으로는 이동하지 않는다. 기존 저장 상태·오류 안내의 status·alert는 유지한다.
- 학생 이름줄·미션 단계 배지의 명도 대비는 4.5:1 이상으로 맞춘다. 안내 창 닫기·도움말·공책 필터·학부모 보조 메뉴 조작 영역은 44px 이상으로 확보한다.
