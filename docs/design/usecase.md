# 유스케이스

- 근거: [프로젝트 기획서](<../outputs/프로젝트_기획서_사고뭉치.pdf>), [요구사항 정의서 v0.3](<../outputs/[기획]요구사항 정의서_사고뭉치.xlsx>), [WBS](<../outputs/[기획] WBS_사고뭉치.xlsx>)
- 요구사항 ID는 요구사항 정의서의 기능 ID(FFH·FFJ·FBF·FBN·FAC·FAD·FAR)
- `(P04)` 형태는 확정 정책 번호, 내용은 [기능명세서 1.4](functional-spec.md#14-확정-정책)
- 용어: 문제 = 미션, 학생 대화 = 미션 안의 되묻기, 학부모 대화 = 자녀 기록에 대한 분석 질의
- 화면 단위 사용자 흐름·역할 간 시나리오는 [사용자 흐름도](user-flow.md)

## 1. 액터

| 액터 | 구분 | 설명 |
|---|---|---|
| 학생 | 사용자 | 제공된 미션을 풀고 되묻기에 답하며, 본인의 학습 과정과 돌아보기를 확인 |
| 학부모 | 사용자 | 연결된 자녀의 기록을 조회하고 분석 대화·일일·주간 리포트로 변화를 확인, 구독 결제 |
| 관리자 | 사용자 | 승인된 범위에서 미션·처리 상태·신고·결제·모델 버전 운영. 콘텐츠·결제·서비스 운영 권한을 구분하며 학생 원문 무제한 열람 불가 |
| 스케줄러 | 시스템 | 주간·일일 리포트 생성, 정기 청구 실행 |
| LLM API | 외부 시스템 | 근거 구절 추출, 되묻기 생성, 분석 대화, 리포트 요약 |
| 토스페이먼츠 (테스트) | 외부 시스템 | 테스트 키로 결제 승인·자동결제·취소/환불·상태 통지, 실결제 미연동 |

### 4.3 UC-09 답변 판정
- 사전조건: 답변 저장 완료
- 기본 흐름

  3. 서술·논술: LLM이 기준표 요소별 근거 구절 추출 → 코드가 구절의 답변 원문 존재 여부 확인 → 요소·배점 기준으로 정답·부분 정답·다시 생각 판정
  4. 판정 결과·근거 구절·기준표 버전 저장, 검증 전에는 "AI 채점(시범)"으로 구분 표시

  - 근거 부족·인용 불일치·짧은 답변·미검증 학년/문항 조합

- 예외 흐름: LLM API 실패는 처리 실패로 기록 (보류와 구분)
- 사후조건: 근거 없는 요소는 충족으로 표시하지 않음, 숫자 레벨 비노출

  2. 문제별 판정 결과·받은 되묻기·보완 답변·확인된 생각 요소·돌아보기·원문 인용을 템플릿으로 구성(LLM 미호출)
  3. 숫자·인용을 원본과 대조 후 저장, 일일 리포트 완료 알림 (UC-22)
- 대안 흐름
  - 기록 없는 날: "기록 없음" 리포트 생성·알림
  - 학생 공개 설정(#206) 비공개: 원문 인용 제외, 수치 유지
- 예외 흐름
  - 생성 실패: 실패 상태·실패 알림, 관리자 재처리 시 새 판 (UC-25)

### 4.10 UC-33 일일 리포트 조회·대화
- 사전조건: 학부모 로그인, 연결된 자녀. 대화는 대상 자녀 프리미엄(분석 대화 하루 30회 공유)
- 기본 흐름
  1. 리포트 목록에서 일일 리포트 선택 → 상세·근거·다운로드(주간과 같음)
  2. "이 리포트로 물어보기" → 자녀·그날·리포트 판을 고정한 분석 대화 생성 (P25)
  3. 질문마다 권한 확인, 그날 리포트와 학습 기록을 근거로 계산·대조 후 답변 (UC-14 3~7)
- 예외 흐름
  - 무료 자녀: 프리미엄 안내, 대화 생성 불가
  - 다른 날 질문: 새 대화로 안내
  - 대조 실패·LLM 장애: 규칙 응답 모드 (P16)

### 4.11 UC-29 풀이 공유 커뮤니티
- 사전조건: 학생 세션. 공유는 커뮤니티 공개 설정 켜짐 + 보호자 선택 동의(`COMMUNITY`), 열람·반응은 그 미션을 마무리한 학생 (P20)
- 기본 흐름
  1. 학생이 커뮤니티 공개 설정을 켬(기본 끔, FN-RET-01)
  2. 미션을 처음 마무리(학습 완료)하면 그 시도의 마지막 답변이 자동 공유됨(학생·미션당 1개, 메모·판정·되묻기 미포함, FN-RET-02)
  3. 마무리한 미션에서 "같은 미션 풀이 보기" → 공유물 무작위 목록, 작성자는 별명·동행 캐릭터로 표시
  4. 정해진 반응 4종을 남기거나 취소(FN-RET-03)
  5. 학부모는 자녀 공유물·받은 반응만 조회
- 대안 흐름
  - 공개 설정을 끄거나 동의 철회·이관 수락: 기존 공유물 비공개, 다시 켜면 설정 비공개분만 복원
  - 다시 풀기: 새로 공유하지 않음
- 예외 흐름
  - 동의 없이 켜기: 거부·보호자 동의 안내 (API 2.9 `COMMUNITY_CONSENT_REQUIRED`)
  - 미션 미마무리 학생의 열람·반응, 본인 글 반응: 거부
  - 신고(UC-20, 대상 `COMMUNITY_POST`): 즉시 숨김 → 관리자 검토 후 다시 공개 또는 계속 숨김 (FN-RET-04)
- 사후조건: 반응 수는 작성자·학부모만, 순위·인기순 비표시

### 4.12 UC-30 포인트·꾸미기 해금
- 사전조건: 학생 세션 (P21·P22)
- 기본 흐름
  1. 학습 완료·되돌아보기 열람·공유·반응·주간 테마 당일 풀이·개근·주간 완주(#483) 때 규칙 값만큼 포인트 적립(FN-RET-05)
  2. 학생·학부모가 잔액·최근 내역 확인
  3. 꾸미기 화면에서 테마·캐릭터·아이템(모자·옷·소품·배경)의 해금 여부·필요 포인트 확인 → 해금(즉시 차감·영구)
  4. 해금한 항목만 선택·착용(FN-RET-06)
- 대안 흐름
  - `lake`·`mungchi`와 잠금 적용 전 고른 항목: 해금된 것으로 표시
  - 이미 해금한 항목 재요청: 차감 없이 성공
- 예외 흐름
  - 잔액 부족·판매 중단 항목 해금, 잠긴 항목 선택: 거부 (API 2.10·3.12)
  - 적립 저장 실패: 학습 응답은 유지, 같은 사건 재요청·주간 테마 조회 때 보충
- 사후조건: 판정 결과와 무관, 회수·소멸·순위 없음

### 4.13 UC-34 주간 테마·꾸미기 아이템 관리
- 사전조건: 관리자 콘텐츠 운영 권한(CONTENT) (P07·P22·P23)
- 기본 흐름
  1. 주간 테마 작성: 학년군·적용 주(월요일)·제목·도입 이야기·요일별 게시 미션(FN-ADM-22)
  2. 검토 요청 → 검토 → 게시(미션과 같은 흐름, UC-24)
  3. 꾸미기 아이템 등록·수정(슬롯·이름·필요 포인트·그림)·판매 중단(FN-ADM-23)
  4. 변경마다 감사 기록
- 예외 흐름
  - 게시 미션이 아니거나 다섯 생각 유형이 빠지거나 겹침, 같은 학년군·주에 이미 게시: 게시 불가 (API 2.8 `WEEKLY_THEME_PUBLISH_INCOMPLETE`)
  - 게시 중 수정: 재검토, 진행 중 시도 영향 없음
- 사후조건: 아이템 삭제 없음, 판매 중단해도 해금한 학생은 계속 사용. 테마·캐릭터 해금값은 코드 상수라 화면에서 바꾸지 않음

## 5. 공통 규칙
- 권한: 학생은 본인 기록, 학부모는 연결된 자녀 기록만 조회·변경. 다른 식별값 요청은 거부 (FBN-01, FBN-05)
- 관리자 권한: 승인된 계정에만 부여, 일반 가입에서 선택 불가 (FBN-02)
- 외부 AI 전달: 작업에 필요한 최소 기록만, 학생 이름·불필요한 식별정보 제외 (FBN-11, FBN-23)
- 시연 데이터: 가상 학생·자체 미션만 사용, AI Hub 원문·가공본은 저장소·화면에 미포함 (FBN-11)
- 생각 유형: 분석하기·따져 보기·새로 만들기·문제 해결하기·돌아보기 5개를 전 화면 동일 사용, 비교·분류·순서·규칙·원인과 결과·추론은 기초 사고력으로 구분 (FAD-05)
- 상태 구분: 기록 없음·표본 부족·판정 보류·처리 중·처리 실패를 구분, 확인되지 않은 값을 임의로 채우지 않음
- 효과 표현: 관찰된 답변 변화와 사고력 향상을 구분, 검증 전 숫자 레벨·등급 비표시
- 대체 응답: P16에 정한 지점(되묻기 질문 은행·분석 대화 규칙 응답·리포트 템플릿 요약)만 허용, 실패 사실·출처·조회 근거 표시
- 결제: 토스페이먼츠 테스트 환경만 사용, 테스트 거래는 실제 운영 기록·매출·학습 통계와 분리 (P13, FBN-13)
- 보관·삭제: 확정 정책을 전 기능에 동일 적용, 삭제된 근거는 이용 불가로 표시 (FBF-20, P09)
- 리텐션: 포인트는 판정 결과와 무관하게 참여로만 적립, 커뮤니티·포인트 모두 순위·인기순 비표시 (P20·P21)
