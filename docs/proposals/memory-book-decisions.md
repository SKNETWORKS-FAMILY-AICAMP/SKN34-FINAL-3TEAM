# 추억 그림책: 도입 전에 정해야 하는 것

- 작성일: 2026-11-23 (동섭)
- 대상: PR을 받는 팀장과 리뷰어. 이 문서만 읽어도 무엇을 정해야 하는지 알 수 있게 썼다.
- 관련 문서: 설계와 구현 기록은 [memory-book.md](memory-book.md), 예시 PDF는 `frontend/web/public/demo/memory-book-sample.pdf`.
- 브랜치: `feature/memory-book` (시험 구현, develop에 합치지 않음).

## 1. 기능 한 줄 요약

유료 구독 학부모가 자녀의 추억 앨범 한 회차(주간 테마 한 주)를 그림책 PDF로 발급받는다. 시작 그림, 요일별 장면 그림과 문제·아이 답변(채팅 모양), 끝 이야기가 A4 가로 8쪽에 담긴다. 새 그림이나 LLM 문장은 만들지 않고 이미 있는 그림과 기록만 배치한다.

## 2. 지금 상태

- core·learning·report·web 구현과 시험이 브랜치에 있고, 로컬에서 서비스를 이어 끝까지(발급 → PDF 생성 → 받기) 확인했다.
- 실제 AWS에서는 돌려 보지 않았다. 운영(prod) 환경 설정, core 공개 API 계약서, `docs/design/` 설계 문서는 아직 고치지 않았다.
- 아래 표의 "지금 구현"은 권장안대로 만들어 둔 값이다. 확정된 것은 **발급 주체**(학부모만)와 **제공 대상**(원문 공개 자녀만) 두 가지뿐이다.

## 5. 도입이 정해지면 따라오는 작업

결정이 아니라 해야 할 일이다. 자세한 것은 [memory-book.md](memory-book.md) 17.2절.

1. 공식 이슈 만들기.
2. `contracts/openapi/core-service.yaml`에 학부모용 API 4개 추가.
3. `docs/design/`의 api-spec, architecture, sequence-diagram, functional-spec, user-flow, usecase 갱신. ERD는 CI(실제 DB 대조) 때문에 3.5.3절로 먼저 넣었다.
4. `infrastructure/gitops/environments/prod/`에 report-worker 그림 받기 주소, 새 큐 구독, core migration 판 번호 추가.
5. 공용 E2E 스택(`compose.e2e.yaml`)에 그림책 설정을 넣고 `memory-book.spec.ts`의 건너뛰기 없애기. 지금 원격 CI에서는 이 e2e 시험을 건너뛴다.
6. develop을 합친 뒤 시험 다시 돌리기(지금은 충돌 없음). core migration 번호 V57이 그때도 비어 있는지 확인.

## 6. 아직 확인하지 못한 것

정하기 전에 알아 두면 좋은 사실이다.

- 실제 AI가 만든 테마 그림의 해상도와 비율. 시험은 데모 그림 7장(PDF 약 1.4MB)으로만 했다. 그림 칸이 거의 정사각이라 가로로 긴 그림은 좌우가 잘린다.
- 아이 답에 이모지가 있을 때 PDF 글꼴로 그려지는지.
- learning 조립 쿼리가 실제 데이터 양에서 충분히 빠른지.
- `reports` 버킷에 수명 주기 규칙이 있는지(C3).
