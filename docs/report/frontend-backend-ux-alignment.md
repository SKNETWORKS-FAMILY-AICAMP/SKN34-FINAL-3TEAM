## UX 교정

- 학생 별도 가입·URL 식별 진입 제거. 학부모 로그인 → 자녀 선택 → 학생 세션 발급. 학생에서 학부모로 돌아가면 다시 학부모 로그인.
- 초3~6. 서술·풀이 단계, 초5~6 논술. 사진·파일·링크 게시를 실제 답변 경로로 제공하지 않음.
- 생각 메모는 학생 본인 전용 초안이며 제출 답변·학부모 기록·리포트·분석 입력에서 제외. 그림 연습은 로컬 UI, 서버에는 문서로 정한 글 메모만 전달.
- 초안 저장·답변 저장·피드백 상태 분리. 409 초안 충돌 시 입력 보존 및 명시적 비교. 답변 제출 멱등 키 유지, AI 실패 재시도는 같은 answerId의 feedback만 재요청.
- 답변 버전 불변, 되묻기 최대 2회, 고르기 정답은 즉시 마무리 가능. DONE 1회 이상 및 서버 nextActions에 따라 마무리. finishedAt 이후 답변 금지, 난이도 필수 돌아보기 저장 후에만 COMPLETED.
- 학부모 전역 자녀·기간을 조회 키에 포함. 주간 리포트는 월~일, 분석 기본 기간은 최근 7일. 기록 없음/소표본/생성 중/실패 구분. 무료는 리포트 수치만·분석 대화 잠금.
- 숫자·인용 근거와 원문 연결. 미확인 숫자 레벨·점수·순위·성적 향상 표현 없음.

## 미구현 API와 계약 유의점

- 정상 앱 실행은 API 모드. `VITE_DEMO_MODE=true`로 실행할 때만 명시적인 화면 시연 모드가 활성화된다. API 오류 때 시연 데이터로 자동 전환하지 않는다.
- 로그인·목록·시도 상세 DTO의 완전한 응답 스키마는 아직 소스에 구현되어 있지 않다. 어댑터는 화면이 요구하는 최소 필드를 검사하고 불일치는 계약 오류로 표시한다. 확인되지 않은 API를 실연동 완료로 표시하지 않는다.
- API 명세 3.1은 NARRATIVE·ESSAY·ORDERING/CHOICE 예시만 제공한다. SOLUTION_STEPS·CLASSIFICATION의 제출 필드 구조는 API 모드에서 임의 전송하지 않고 계약 확정 필요로 안내한다. 화면 시연에서만 별도 프론트 도메인 표현을 사용한다.
- 초안 충돌은 API 명세 3.6의 `latest: {version, content: {answer, memo}}`를 화면용 초안으로 정규화한다. 숫자 버전은 If-Match용 따옴표 버전으로 보존한다.
- 리포트는 응답 자녀·기간과 숫자·인용 검증 결과를 확인한다. 재생성을 요청한 뒤 이전판이 반환되어도 새 판 완료로 표시하지 않는다. 저녁 질문은 실제 응답 필드를 사용하며, API 모드에서 프론트가 임의 생성하지 않는다.
- 실제 백엔드 배포·인증·LLM·PG·다운로드·원격 CI 검증과 화면 시연 테스트는 별개다. 실행 결과는 작업 완료 시 아래에 기록한다.

## 시각 구성과 자산

- 공책 작업물을 중심에, 민트색 자녀/학습 탐색 패널을 오른쪽에 둔다. 작성할 때는 피드를 벗어나 넓은 활동지와 도구 레일에 집중한다. 아이보리 종이·절제된 색·선생님형 존댓말을 유지한다.
- 기존 외부 시안 HTML의 CSS와 정적 그림을 복사해 React에 적용했다. 원본 시안·이전 캡처는 이동하거나 덮어쓰지 않았다.
- `public/brand.jpg`는 사용자가 제시한 2안 로고, `public/demo/atlas.jpg`는 기존 시안의 생성형 펠트 교구 예시다. 실제 수집 데이터/학생 작품이 아니다. 교구 그림은 시연 모드에서만 표시한다.
- 테스트용 새 캡처 폴더: `C:/Users/playdata2/outputs/classroom-repo-20261026/` (이 작업에서 새로 생성).

## 변경 파일의 연결

`router.tsx` → `ClassroomApp.tsx` → 학생 `StudentWorkPage.tsx` / 학부모 `ParentFeatures.tsx` → `useClassroom.ts` → `ClassroomGateway` → 실제 core 어댑터 또는 명시적 시연 어댑터.

조회 키에 역할·자녀·기간을 포함하고, 인용 원문은 현재 공책 목록에 의존하지 않고 해당 자녀의 상세 경로로 조회한다. 저장 실패 상태에서 작성기를 나가면 확인을 요구하며, 409에서는 최신 초안과 현재 입력을 선택 전까지 덮어쓰지 않는다.

## 검증

- `npm run build`: TypeScript와 Vite 빌드 통과. 기본(API) 모드 빌드.
- `npm run lint`: 경고·오류 없음.
- `npm test`: 단위·API 어댑터 테스트 12개 통과. 멱등성, 답변 보존, AI 재시도, 409 초안, 메모 비공개, 자녀 범위, 무료 제한, 빈 주/소표본/이전판, KST 경계를 확인.
- `tests/browser-smoke.mjs`: 실제 Chromium 화면 조작 통과. 미션 → 제출 → AI 실패 → 피드백만 재시도 → 추가 답변 2회 → 마무리 잠금 → 난이도 필수 돌아보기 → 공책 복귀. 학부모 리포트 → 원문 → 같은 자녀/기간 분석, 자녀 전환 후 이전 결과 제거, 무료 분석 잠금 확인.
- 노트북 1440×900, 태블릿 가로 1024×768·세로 768×1024, 보조 모바일 390×844에서 공책 수평 넘침 없음. 태블릿 작성기에서 충돌 비교·저장 실패·나가기 확인·재시도 확인. pageerror 없음.
- 기본 API 빌드에서 로그인 404 응답 스텁을 넣어 오류 표시와 예시 데이터 자동 대체 없음 확인. **실제 core 인증·DB·LLM 통합 검증이 아니다.**
- 마무리 전 원격 재확인: `HEAD...upstream` 0/0. 이후 생성된 로컬 변경은 커밋·stash·push하지 않았다.
