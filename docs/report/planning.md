## 2. 국어(M2) 우선과 생각 유형 매핑 (#213)

### 2.1 결정과 배경

| 항목 | 내용 |
|---|---|
| 배경 | 10/29 멘토링에서 M2 숫자(서술 0.3·논술 0.4)가 서비스 기준(약 0.7, 참고치이며 허용 기준 아님)에 못 미쳐 한 과목에 집중하라는 권고 |
| 결정 (11/1) | 국어(M2) 우선, M1(수학 풀이 과정)은 후순위. 한 과목을 먼저 완성한 뒤 확장 |
| 생각 유형 (11/2) | 다섯 유형 이름·코드 유지. 초5·6은 분석하기·따져 보기·새로 만들기·돌아보기를 국어 서술·논술로, 문제 해결하기는 예외로 수학 풀이 |
| M2 사용 범위 (11/2) | 자체 미션(처음 보는 주제)에도 M2를 쓰는 방향 → 발표 대표 숫자는 처음 보는 주제 값. 허용 기준 자체는 미정 |
| 중간 발표 (11/6) | 시연보다 기획 근거·구현 흐름·시스템 준비 현황 위주 |

멘토링의 0.3·0.4는 초기 모델의 QWK(처음 보는 지시문 조건)이고, 서비스 후보 모델의 0.685·0.700은 Pearson(학습한 주제)이라 직접 비교하지 않는다.

NFR-AIQ-02에서 바뀐 것(M2 담당이 쓰던 방식을 설계에 옮김):

| 이전 | 지금 |
|---|---|
| AI Hub 71818·71819로 항목 점수 학습 | 서술 71818, 논술 545 에세이(채점자끼리 일치가 더 높게 보고됨) |
| 지시문 단위 학습·평가 분리 | 같은 글은 학습·평가에 섞지 않고, 처음 보는 주제는 주제 단위로 떼어 평가(학습한 주제 평가도 함께 보고) |
| 기준선에 학습 없는 LLM 포함 | 제외(AI Hub 데이터를 외부 LLM에 보내지 않음). 학습한 공개 LLM(LoRA)과 비교 |
| QWK·균형정확도·과대/과소 판정률 | Pearson 상관을 사람끼리 상관과 함께 보고 |

바꾸지 않은 것: 유형 이름·코드(API·ERD·프론트·리포트 공용 값), api-spec·OpenAPI·ERD 계약(scoring 계약의 3.0·3.1 반영은 [ai](ai.md) 4.1).

### 2.2 유형별 성취기준

기획서 5.3(1)의 유형별 평가 요소에 가장 가까운 초5·6 성취기준. 문장은 교육부 고시 제2022-33호 기준이며 [경기도교육청 수업-평가 계획 예시 자료](https://www.goe.go.kr/resource/goe/na/bbs_2675/2026/02/116dc7a4-254a-44fe-9e77-3e908ecc5ff3.pdf)에서 문구를 대조했다.

| 유형 | 성취기준 | 고른 이유 |
|---|---|---|
| 분석하기 | `[6국05-03]` | 인물·사건·배경 파악 기준이라 사건의 원인과 관계 설명에 맞춤. 까닭 잇기는 미션 질문에서 요구. `[6국02-02]`는 보조 후보 |
| 따져 보기 | `[6국01-02]`·`[6국03-02]` | 기획서 예시와 현재 시드(초6) 기준 |
| 새로 만들기 | `[6국05-05]` | 경험을 갈래로 표현하는 기준으로 연결·변형에 가까움. 다른 생각·왜 나은지는 미션 질문에서 요구 |
| 문제 해결하기 | `[6수03-14]` (수학, 예외) | 평가 요소가 풀이 틀과 맞고 최종 답을 정답 키 규칙으로 판정 가능. 국어 `[6국02-04]`는 따져 보기와 겹쳐 보조. "한 과목 먼저"와의 충돌을 확인하고 예외로 유지 |
| 돌아보기 | `[6국03-05]`·`[6국06-04]` | 기획서 예시와 현재 시드(초6) 기준. `[6국05-06]`도 후보 |

- 수학 풀이 문제 해결하기는 M2를 쓰지 않음(최종 답 규칙 + 풀이 단계 LLM 근거 대조)
- 초3·4는 문구 대조 자료를 찾지 못해 성취기준 미정. M2를 쓰지 않는 학년이라 미션 작성 시 고시 원문으로 정함
- 현재 데모 시드와 차이: 분석하기(과학)·새로 만들기(도덕)가 과목이 다름. 도덕은 M2 서술 학습 데이터(국어·사회·과학·수학)에 없는 교과. 문항 교체는 learning 후속 이슈

### 2.3 M2 중간 결과 (11/2 기준)

허용 기준이 정해지지 않아 통과·미달 판정은 하지 않음. 활성화 판단(NFR-AIQ-06, 11/22) 전까지 숫자는 바뀔 수 있음. 지표는 Pearson 상관, 대표 숫자는 처음 보는 주제에서 모델 대 전문가 평균.

| 구분 | 모델 | 모델 대 전문가 평균 | 사람끼리 1대1 |
|---|---|---:|---:|
| 처음 보는 주제 (대표) | 논술 3.1 설정, 주제 10개 제외 | 총점 0.45~0.48 | 0.560 |
| 처음 보는 주제 (대표) | 서술 3.0 설정, B안 3 fold 평균 | 총점 0.538 | 0.694 |
| 학습한 주제 (참고) | 서술 3.0 | 총점 0.685 | 0.694 |
| 학습한 주제 (참고) | 논술 3.1 | 총점 0.700 (표현 0.481) | 0.718 |

- 서비스 후보 모델은 모든 주제를 학습하므로 처음 보는 주제 값은 일부 주제를 뺀 평가용 모델로 구함
- 약한 곳: 처음 보는 주제 성능이 크게 낮음, 논술 표현이 사람끼리보다 낮음. 학습한 주제만 출제하는 문항 은행 방식은 주제가 서술 12개·논술 6개뿐이라 어려움
- 같은 설정도 실행마다 ±0.02 흔들림
- 출처: M2 담당 정리(11/2), [ml/m2 README](../../ml/m2/README.md). 예측 CSV 등 계산 원자료는 저장소 밖

### 3.6 설계 판단

- 포인트 적립에 새 메시지를 두지 않음: 적립 사건은 모두 core가 learning 응답을 프록시하는 경로에서 확인 가능
- 일일 리포트를 `period_type`으로 일반화: 작업·재처리·Outbox·알림·다운로드 경로 재사용. 월요일 일일·주간의 `period_from`이 같아 정기 생성 UK·재생성 UK·revision 잠금에 `period_type` 추가
- 작성자 별명은 core가 붙임: 다른 학생에게 학생 ID를 노출하지 않으려고 core가 응답에서 지움
- core `conversation.report_id`·`report_revision` 추가: core가 메시지마다 그 판을 읽어 ai에 넘겨 ai → report 의존을 만들지 않음
- 포인트 원장 사건 키는 문자열 `source_key`: 되돌아보기·개근·주간 완주(`weekStart`), 당일 풀이(`weekStart:day`), 반응(복합 키)은 uuid가 없음
- 공유물은 학생·미션당 1개: 다시 풀기마다 공유 포인트가 늘고 반응이 다른 답에 붙는 문제 방지
- 새 NOT NULL 컬럼은 기본값 없이 준비·최종 마이그레이션으로 나눔: 검증 스크립트가 컬럼 기본값을 금지

### 3.7 남은 확인 사항

- 화면설계서 반영과 화면 ID 부여
- 요구사항 정의서 개정 여부

## 4. 설명 sLLM 데모 범위 재포함 (#473, 11/10)

P15로 범위에서 뺀 설명 sLLM(FN-RPT-09, NFR-AIQ-03)을 12/7 데모 범위에 다시 넣는다. M2 점수는 판정 교차 확인에만 쓰이고 숫자 비표시 정책 때문에 학부모에게 전달되지 않는다. 설명 sLLM은 학생 글과 M2 항목 점수로 학부모가 읽을 설명을 만든다.

sLLM이어야 하는 이유: 학습 데이터인 AI Hub 71818 전문가 이유 문장은 외부 LLM API로 보낼 수 없다.

| 항목 | 결정 | 근거 |
|---|---|---|
| 범위 | 12/7 데모 포함, 허용 기준 11/22(NFR-AIQ-06) | 기존 설계(FN-RPT-09·UC-16) 재사용 |
| 학부모 말투 | 규칙 후처리(점수·등급·숫자 표현 제거, 학부모용 문장 틀) | 전문가 문장은 채점자 말투. 생성형 AI로 바꾼 문장은 학습에 쓸 수 없음(NFR-DAT-03) |
| 학습 위치 | RunPod, AI Hub 데이터만 | M2 학습 환경 재사용 |
| 생성 위치 | EKS 안 CPU 양자화 모델 | AWS 서울 리전은 이미 개인정보 처리 위탁 목록에 있어 동의서 변경 없음. GPU 할당량 대기 위험 없음 |
| 실행 구조 | OpenAI 호환 sLLM 서버 평소 0대, KEDA cron으로 월요일 배치 시간만 1대. report → ai → sLLM | 기존 리포트 서술 흐름·검사·버전 기록 재사용 |
| 주기·단위 | 주 1회, 대표 답변 최대 3개에 답변별 설명 | 모델이 답변 1개 단위로 학습. 주 1개 요약은 품질·인용 대조가 어려움 |
| 대상 | 프리미엄(P13), 원문 공개(FN-RPT-07), M2 승인 범위 | 기존 정책과 같은 기준 |
| 실패 | 설명만 빼고 발행, "설명 미포함" 표시 | 리포트 핵심 흐름을 막지 않음(P16) |
| 저장 | report_db `report_item.item_type = EXPLANATION`. `narrative.modelExplanation`은 계약 유지로 null | 답변 근거 연결·검증 표시 재사용 |

확인 필요(#475): AI Hub 71818 피드백 문장의 서비스 이용 조건, CPU 생성 시간 실측(가정 건당 20~30초)과 설명 대기 상한, 기본 모델 비교 결과와 허용 기준.
