# #88 M1 수학 검사 비활성 계약 검토

## 목적과 완료 범위

M1이 미학습인 동안 AI가 수학 검사 API를 호출해도 404나 임의 판정을 받지 않도록, 인증된 요청에 `{active:false}`를 반환한다. 이슈 #88의 명시적인 **미학습 시 비활성 계약까지만 완료** 조건과 담당자 답변을 적용했다. 수학 모델 추론 기능 전체를 완성한 것은 아니다.

## 기반과 병합

- #87 `344cfdf` 위에 구현했으며 #85·#86 코드도 포함한다.
- 2026-10-29 최신 develop `26f3788`을 병합했다. 분석 대화 변경과 API 문서가 자동 병합됐고 미해결 충돌은 없다.
- 브랜치: `feature/scoring-m1-checks`. 선행 #85 → #86 → #87 이후 #88 순서로 검토·병합한다. 선행 PR이 미병합이면 develop 대상 diff에 선행 변경도 포함된다.

## 계약

`POST /internal/m1/checks`, `X-Internal-Token` 필수.

```json
{
  "problem": "2 더하기 3은?",
  "answerKey": "5",
  "solution": {"steps": ["2에 3을 더합니다."], "finalAnswer": "5"}
}
```

- problem = 미션 문제, answerKey = 정답 키 finalAnswer, solution = 학생 풀이.
- 문자열 타입, 필수 항목, 공백 입력, steps 배열과 알 수 없는 항목을 검증한다. 단계 순서·빈 슬롯은 보존하되 내용 있는 단계가 하나 이상 필요하다.
- 유효 요청: 200 `{active:false}`. 인증 누락·불일치: 401. 입력 오류: 400 RFC 9457.
- 현재는 승인된 M1 추론기가 없으므로 모든 입력이 비활성이다. M2로 대체하거나 정답 문자열만 비교하지 않는다. core 메타데이터 등록만으로 활성화하지 않는다.
- 실제 추론이 없으므로 M1 사용량도 발행하지 않는다. 원문 로그를 추가하지 않는다.
- 공통 인증·오류·라우터 구조 재사용. 새 레지스트리나 사용량 발행기를 만들지 않는다.
