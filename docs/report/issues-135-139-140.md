# #135·#139·#140 서비스 클라이언트 재사용과 테스트 보강

## 기준과 제출 방식

develop `18c9c11`에서 `feature/service-client-test-hardening` 브랜치를 만들고 #135 → #139 → #140 순서로 적용한다. 이슈별 커밋·완료 조건을 구분하고 최종 PR은 develop 대상으로 하나로 제출한다. 아직 GitHub 이슈·PR을 자동 변경하지 않는다.

## #135 설정과 report 조회 클라이언트

| 설정 | 결정·근거 |
|---|---|
| report `ai_url` | 유지. 기본 worker가 이미 해당 URL로 AiClient를 조립하므로 중복 연결하지 않음 |
| report `core_url`, scoring `core_url` | 유지. 별명/삭제 완료 조회와 활성 모델 기동 조회에서 실제 사용 |
| ai `scoring_url`, `core_url` | 유지. 미병합 #69 교차 확인·#68 활성 버전 조회에 명시된 연결 대상. config 주석에 용도 표시 |
| ai `learning_url` | 분석 도구 등에서 사용하므로 유지 |

report 조회 API의 learning HTTP·S3 클라이언트를 lifespan에서 한 번 만들고 모든 조회에 재사용한다. HTTP 요청 훅은 각 요청의 ContextVar에서 권한을 읽으므로 이전 학생의 헤더를 공유하지 않는다. S3 생성·종료는 블로킹 작업이므로 기존 run_blocking을 재사용한다. startup 실패·요청 예외·종료 예외에서도 HTTP와 DB를 정리한다. API·이벤트·DB 계약 변경은 없다.

단위 테스트는 합성 자격 증명·HTTP transport·storage를 사용한다. 실제 AWS 계정·버킷·모델은 사용하지 않는다. 기존 MinIO 통합 테스트는 별도 합성 계정/버킷으로 계속 실행한다.

## #139 report 직접 테스트

worker.run 운영 조립·큐 구독·relay·종료, run_blocking 취소와 스레드 완료, presentation 원본 불변·권한 투영, verifier 숫자·인용 검증, 조회 응답 스키마를 직접 확인한다. 기존 렌더링/서술 통합 검증도 유지한다.

Outbox 영구 실패 중 다른 학생 발행·같은 학생 순서·격리·수동 복구는 #131 PR #175의 실제 PostgreSQL/RabbitMQ 테스트를 재사용한다. #175는 작업 시작 시 OPEN이며 이번 PR에 코드를 중복 포함하지 않는다. #131 병합 후 최종 develop 통합 상태를 검증해야 한다.

## #140 scoring 공통 테스트

기존 #85~#88의 M2·M1·모델 교체 테스트를 유지하고 브로커 연결 복구·readiness·종료, 이벤트 봉투 스키마, 내부 헤더·학생 scope·trace 전파 및 설정 로딩 공백을 보강한다. 미학습 M1을 실제 모델 검증 완료로 표현하지 않는다.
