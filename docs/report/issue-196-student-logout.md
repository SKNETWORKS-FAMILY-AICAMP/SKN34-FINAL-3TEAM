# 학생 종료와 보호자 로그인 전환 (#196)

## 문제와 결정

61c26a6 실제 Chrome 검증에서 PIN 로그인은 보호자 세션·refresh를 유지하고 별도 학생 세션을 만들었다. 그러나 학생 홈의 보호자 전환 버튼은 공통 `/auth/logout`을 호출해 같은 브라우저의 보호자 세션도 폐기했고, 해당 탭에 남은 `loginPath=/student/login` 때문에 `/login` 진입이 PIN 화면으로 되돌아갔다.

사용자가 승인한 범위는 학생 세션만 종료하고 기존 보호자 세션을 유지하는 것, 학생 탭에서는 보호자 인증을 요구하는 것이다. 기존 보호자·관리자 전체 로그아웃 정책은 유지한다.

## 구현 경로

- 웹 게이트웨이는 학생 모드에서만 `POST /auth/student/logout`을 호출한다. 학생 refresh 자동 재시도와 다른 탭으로의 LOGOUT 방송은 하지 않는다.
- 기존 AuthController → AuthService에서 학생 Bearer를 검증하고 해당 auth_session만 폐기한다. 보호자 refresh·등록 기기 쿠키를 읽거나 만료시키지 않는다. 기존 Origin·X-Requested-With 검사를 유지한다.
- 누락·위조·만료 Bearer는 401, 다른 역할·출처는 403이다. 학생 401은 로컬 자격증명을 정리하되, 저장소·전송 장애는 오류로 남기고 학생 세션을 성공 종료한 것처럼 표시하지 않는다.
- 학생 홈의 종료와 PIN 화면의 보호자 로그인 버튼은 탭 내부 전환 이벤트로 SessionProvider의 세션·쿼리 캐시·loginPath를 함께 정리한다.
- 비밀정보 없는 sessionStorage 표식 하나로 보호자 로그인 대기 상태를 탭에 유지한다. 새로고침에서도 보호자 쿠키 자동 복원을 차단하고 Google OAuth 완료 뒤 부모·관리자 access를 수령하면 표식을 지운다. access·refresh·PIN은 저장하지 않는다.
- 다른 탭의 보호자 로그인 알림은 활성 학생 탭 또는 보호자 로그인 대기 탭의 역할을 바꾸지 않는다.
- MSW에도 학생 종료 경로를 추가하되 실제 쿠키·세션 분리는 서버·브라우저 검증과 구분한다.

## 검증

2026-10-31, `61c26a6` 기반 추가 변경을 검증했다.

- core: `PublicAuthFilterTest` 9개 통과. `AuthFlowIntegrationTest` 12개·`StudentDeviceAuthTest` 11개는 검증 컨테이너의 RabbitMQ 정의 파일 누락 및 테스트용 만료 JWT 생성 오류를 수정한 뒤 재실행해 전부 통과했다. 유효한 학생 종료, 보호자 refresh·다른 학생 세션·기기 자격증명 보존, 누락·위조·만료·부모 Bearer 및 잘못된 Origin 거부를 포함한다. 총 영향 범위 32개이며 core 전체 테스트 실행 결과는 아니다. `bootJar` 성공.
- 웹: 전체 148개 테스트 통과. 최종 경로 가드 보완 후 학생 로그아웃 회귀 4개·lint·build·운영 mock 제외 검사를 다시 통과했다. 기존 관리자 화면 immutability 경고 1건과 번들 크기 경고는 남아 있다.
- 계약: 루트 94개 테스트의 실패 모듈(신규 경로 개수와 Windows 임시 폴더 권한) 15개를 보완·재실행해 통과했다. core OpenAPI 표준 검사 통과.
- `git diff --check` 통과. 새 production 의존성이나 DB 마이그레이션 없음.

### 실제 Chrome·MSW OFF 확인

기존 검증용 자녀·등록 기기와 실제 Google 계정을 사용했으며, PIN 입력은 사용자가 직접 했다. core·PostgreSQL·Redis는 실제 구현이다.

1. 보호자 탭이 로그인된 상태에서 별도 학생 탭의 PIN 로그인 성공. 동일 보호자 세션·버전·유효 refresh를 유지하고 refresh 없는 학생 세션이 추가됐다.
2. 학생 홈에서 보호자 전환을 누른 후 서버에서는 해당 학생 세션만 `revoked=true`, 보호자 세션은 `revoked=false`, 유효 refresh 1개를 유지했다. 보호자 탭 새로고침도 로그인 없이 복원됐다.
3. 초기 UI 재검증에서 보호된 학생 RoleLayout의 기본 PIN 경로와 전환 요청의 경합을 확인했다. RoleLayout·LoginGate 모두 명시적 보호자 진입을 우선하도록 보완했다.
4. 최종 PIN 화면의 보호자 버튼은 `/login`으로 이동했다. 그 화면을 새로고침해도 보호자 쿠키로 자동 진입하지 않았다.
5. 추가 PIN 입력을 요구하지 않도록 최종 학생 홈 버튼은 동석 학생 세션으로 재검증했다. 동일 StudentWorld→종료→RoleLayout/LoginGate 경로가 `/login`으로 이동했고, 새로고침 후에도 Google 로그인 화면을 유지했다. PIN 종료의 서버 세션 보존은 2번에서 별도로 확인한 결과다.
6. 실제 Google 재로그인 완료 후 해당 탭은 보호자 대시보드로 복원됐고, 다른 학생 탭은 부모 역할로 자동 변경되지 않았다.

브라우저 검증은 동일 Chrome 프로필의 별도 탭 기준이다. 별도 물리 기기, 원격 CI, 배포 검증으로 확대하지 않는다. PIN·쿠키·토큰 원문을 결과 문서에 기록하지 않는다.

API 본문·기존 초안/미션 계약·DB 마이그레이션·production 의존성은 변경하지 않는다. #195 캐시 변경은 기존 커밋 그대로 유지한다.
