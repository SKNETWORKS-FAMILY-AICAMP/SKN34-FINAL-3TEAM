# 리포트 설명 sLLM 출력 사람 검수 기록 (#883, 2026-11-23~24)

리포트 대표 답변 상세 설명(LoRA Gemma `explain`)의 출력을 사람이 읽고, 어색한 출력을 지적하면 원인을 찾아 고친 과정을 시간 순서로 적는다. 검수자는 김재현이고 출력 50건의 사람 검수를 마쳤다(NFR-AIQ-03).

## 1. 범위

- 문항은 서비스 데모 시드(`backend/learning-service/db/seed/demo_missions.sql`)의 실제 문제 전문과 기준표 항목이다. 설명 대상 범위(서술 초5·6, 논술 초4~6)의 미션 7개를 썼다
- 학생 답은 팀이 쓴 가상 글이다. 미션마다 잘 쓴 글과 부족한 글을 섞은 12건(R01~R12, 상 5·중 2·하 5)과, 한 문장만 보완한 전·후 3쌍(P1 휴대폰, P2 피구, P3 컵)을 썼다. 항목별 판정과 M2 점수도 가상이다. 실제 아동 글과 AI Hub 원문은 쓰지 않았다
- 모델은 튜닝 모델(explain LoRA)만 썼다. 기본 Gemma와 외부 API는 쓰지 않았다(2.8)
- 출력은 저장소 밖 시험 스크립트로 만들었다. 정리·검사 함수는 서비스 코드(ai-service `report_explanation`)를 가져다 썼다. 이 기록 시점에 서비스 코드와 프롬프트 버전은 바꾸지 않았다
- 검수 페이지(HTML)와 모델 출력 원문은 저장소에 넣지 않았다. 아래 시각은 KST다

## 2. 시간순 지적과 수정

각 항목은 "검수자 지적 → 원인 → 고친 방법 → 결과" 순서다. 검수자 지적이 없는 항목은 비교 실행에서 드러난 문제를 적었다.

### 2.1 서비스 형식 출력 확인 (11-23 18:14~18:44)

- **요청:** 서비스에 실제로 있는 문제와 학생 답, 현재 리포트 양식에 맞춰 12건을 검수
- **@5(코드 브랜치 `codex/gemma-grounded-explanation`):** 12건 중 9건만 설명이 붙었다. 보완할 지점은 12건 모두 비었고(모델이 보완 항목 번호를 한 번도 채우지 않음), 논술 3건은 JSON 형식 오류로 빠졌다. R12는 기호만 남은 출력이 검사를 통과했다
- **@4(현재 develop):** 10건에 세 칸이 나왔지만 분량이 248~1,795자로 들쭉날쭉했고, R01·R07은 같은 말을 되풀이했다. R03은 깨진 출력이 검사를 통과했다
- **학습 형식(11/20 시험과 같은 평문 지시 + 9항목 점수):** 12건 모두 세 칸이 나왔고 깨진 출력이 없었다. 분량 380~781자, 원문과 일치한 인용 40/47
- **판단:** 품질 차이의 주원인은 프롬프트 버전보다 입력 형식(JSON 칸·긴 지시문은 LoRA가 학습 때 본 적 없는 형식)으로 봤다

### 2.2 "@4는 너무 길다, 줄이고 균일하게" (18:48)

- **고친 방법 1:** @4 지시만 바꿔 목표 분량을 1,000~1,400자에서 550~750자로, 칸별 문장 수를 고정했다

- **고친 방법 2 ("학습 형식으로 조정", 18:55):** 학습 형식 지시 끝에 "상세 분석 네 문장, 보완할 지점 세 문장, 개선 방안 세 문장"을 덧붙이고, 코드가 칸마다 그 문장 수까지만 남긴다

### 2.3 채점을 다시 하지 않고 판정 근거로 설명하기 (19:11~19:23)

- **검토 의견:** 모델이 이미 채점된 답안을 처음부터 다시 평가하지 말고, 서비스가 가진 문제 요구사항과 항목별 판정을 근거로 설명해야 한다
- **안 A:** 학습 형식은 유지하고 `[문제]`, 칸 이름을 붙인 `[글]`(주장·까닭·반대 의견에 답하기), `[판정]`을 덧붙였다. 필수 항목에 미충족이 없으면 코드가 보완 칸을 뺐다. 보완 전·후 3쌍을 더해 18건으로 시험했다
- **결과:** 다 쓴 답안에 붙던 엉뚱한 지적이 사라졌다(R08이 목줄·놀이터 대안을 정확히 짚음). 그러나 보완 후 답안(P1b·P2b·P3b)도 상세 분석에서 고친 부분을 여전히 "부족하다"고 썼고, R04는 문제 속 인물 지우의 까닭을 "자녀가 제시한 까닭"으로 썼다
- **코드 규칙 추가:** 문장 단위로 다음을 뺐다
  - 점수 암시: 채점 항목 이름 + "에서 다소 아쉬운" 등, "핵심어"
  - 문제 속 인물의 말: 따옴표 인용이 문제에는 있고 학생 글에는 없음
  - 다 쓴 답안의 지적: 필수 항목을 모두 충족한 답안의 상세 분석에서 "그러나…", "부족", "아쉬" 문장
- **결과:** 상세 분석은 깔끔해졌지만, 보완할 지점의 방향이 틀린 경우(P1a "다른 학교 친구들이 쓰는 이유를 설명하라")는 규칙으로 못 고쳤다

### 2.4 "기본 Gemma는 쓰지 않는다" → 튜닝 모델 2회 호출 (19:24~19:33)

- **결정:** 보완할 지점을 기본 Gemma에 맡기는 안은 쓰지 않고 튜닝 모델만 쓴다
- **고친 방법:** 미충족 필수 항목이 있는 답안만 튜닝 모델을 한 번 더 부른다. 그 항목 하나의 요구사항과 학생이 관련해 쓴 문장만 주고 보완할 지점·개선 방안을 받는다. 개선 방안 끝에는 기준표 힌트 질문 하나를 붙였다
- **결과:** 미충족 8건 중 7건이 판정의 미충족 항목을 정확히 짚었다(P1a "'제 생각은 달라요'라고 밝혔지만 왜 타당하지 않은지 이유가 없다", R04는 자녀가 직접 쓴 반박 문장을 짚음). 남은 문제는 아이 대신 완성된 답 문장을 써 주는 개선 방안, 지시문 말투("요구에 대한 설명이 부족") 노출, 다 쓴 답안의 상세 분석이 2~3문장으로 짧아지는 것이었다

### 2.5 "R03 출력이 끝까지 안 나온 것인가" (19:38)

- **원인:** 모델은 끝까지 썼다. 다 쓴 답안이라 코드가 보완 칸을 빼고, 상세 분석 4문장 중 2문장이 규칙(점수 암시, 다 쓴 답안의 지적)에 걸려 칭찬 2문장만 남았다
- **고친 방향:** 다 쓴 답안은 처음부터 "잘된 점 네 문장"으로 받는다(2.6)

### 2.6 "보완할 점이 없으면 안 된다, R02처럼 구체적으로" (19:49~20:03)

- **지적:** 학생 글에 보완할 점이 하나도 없는 설명은 안 된다. 미충족 답안(R02)처럼 항목을 구체적으로 지시한 출력이 좋으니 이 방식으로 균일하게 15건을 뽑는다
- **고친 방법:**
  - 1차 호출은 상세 분석에 "자녀가 쓴 내용과 잘된 점 네 문장"만 쓰게 한다. 규칙 적용 뒤 3문장이 안 남으면 반복 억제(1.1)를 켜고 한 번 다시 받는다
  - 2차 호출의 보완 대상을 모든 답안에 하나씩 코드가 정한다. 미충족 필수 항목이 있으면 그 항목(6건), 다 쓴 답안이면 선택 항목을 골라 "잘 쓴 부분을 인정하고 한 걸음 더"(9건)
- **결과:** 15건 모두 세 칸, 평균 544자, 362~637자, 표준편차 69자. 남은 문제는 문제에 없는 정보 요구(R08 기사 날짜·신문 이름, P3b 열이 이동하는 속도), 칭찬 쪽 점수 표현(R03), 인용 어긋남(R04 원문 "저는"을 "나는"으로)이었다

### 2.8 절충안과 질문 없는 버전 (00:48~01:07)

- **절충안 (00:49):** 미충족 답안은 그대로 두고, 다 쓴 답안은 보완 2문장·개선 1문장으로 줄이며 "문제와 글에 나온 상황 안에서만 제안하라"를 넣었다. 질문은 판정을 통과할 때만 붙였다

### 2.9 "지우의 까닭 두 개는 각각 휴대폰을 써야 하는 이유가 될까요?" (01:28~01:53)

- **1차 지적 (01:28):** 이런 부자연스러운 출력은 손봐야 한다
  - 시도: 학생 화면용 존댓말 힌트를 부모가 아이에게 하는 말로 바꿨다("될까요?" → "될까?", "예를 들어 '…' 하고 물어봐 주세요", 문제 속 인물 앞에 "문제에 나온")
- **2차 지적 (01:43):** 그 문장은 의미가 없고 비문에 가깝다. 실서비스에 들어가면 신뢰성이 크게 떨어진다
  - 원인: 학생용 힌트를 맥락 없이 학부모 글에 끼워 넣었고, 코드가 "문제에 나온"을 덧붙여 더 어색해졌다
  - 고친 방법: 리포트 설명에서 기준표 힌트 붙이기를 뺐다. 리포트에는 모델이 쓴 문장과 학부모용으로 검토된 문장만 넣는다
- **3차 지적 (01:44):** 말투가 문제가 아니라 의미 없는 단어의 나열이다. 아이는 이유라고 생각했으니 까닭이라고 적었다
  - 원인: "까닭"과 "이유"가 같은 말이라 "지우가 든 이유가 이유가 될까?"를 묻는 셈이고, 답이 정해져 있다. 물으려던 것은 "그 까닭이 타당한가"였다. 이 문장은 모델이 아니라 데모 시드의 힌트 원문이라 학생 화면에도 그대로 나간다
  - 수정 예시: "'다른 학교 친구들도 다 쓰니까'라는 말만으로 우리 학교도 휴대폰을 써야 한다고 할 수 있을까요?" 시드 힌트 15개 점검은 학생 화면에 영향이 있어 후속으로 둔다(4절)
- **힌트 없이 재생성 (01:45):** 15건 모두 세 칸, 평균 455자, 364~547자, 표준편차 53자로 이번 검수에서 가장 고르다. 비문이나 앞뒤가 안 맞는 질문은 없다
  - 남은 문제: 지시문 문장 노출(R11 "자녀가 이미 쓴 부분을 먼저 인정하며"), 기준표 설명 문장 노출(P2b), 한 칸 안의 같은 지적 반복(R02 "미흡·부족·미흡"), 아이가 겪었는지 모를 경험 요구(R03, R05)

### 2.10 질문 포함 여부 결정 (01:56)

- **결정:** 질문이 들어가는 쪽이 품질상 낫다. 다만 15건 모두 멀쩡한 질문이 나올 때만 넣는다. 이상한 질문이 하나라도 섞이면 질문 없는 버전(2.9 재생성)을 기준으로 둔다
- 11-24 오전에 같은 설정으로 재실행해 출력이 같은지 보려 했으나, 로컬 실행 환경(Docker) 문제로 실행하지 못했다

## 4. 남은 일

- 지시문 문장·기준표 설명 문장이 출력에 그대로 들어가면 빼는 규칙(R11, P2b)

- 서비스 반영: 새 프롬프트 버전 번호, 논술 M2 점수(3항목)를 학습 형식 9항목으로 바꾸는 방법, 75초 마감 안에 2회 호출이 들어오는지 확인
