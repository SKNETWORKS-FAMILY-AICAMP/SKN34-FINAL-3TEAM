# #289 학부모 탈퇴 전 자녀 이관: 구현과 통합 검증

2026-11-03. 기준 develop `4d900029c4fc5a14a04c200a31e83605fe700f4f`.
작업 브랜치 `feature/289-guardian-transfer`. 기존 로컬 시제품을 최신 develop에 통합했으며 운영 배포는 하지 않았다.

## #275에서 바로잡은 내용

[#289](https://github.com/SKNETWORKS-FAMILY-AICAMP/SKN34-FINAL-3TEAM/issues/289)는 [#275](https://github.com/SKNETWORKS-FAMILY-AICAMP/SKN34-FINAL-3TEAM/issues/275)의 다중 학부모 연결 전제를 바로잡는 후속 이슈다. 현재 보호자를 여럿 유지하고 리포트 설정의 기준 보호자를 고르는 방식은 적용하지 않는다. 상대방 동의와 재인증을 거쳐 현재 연결을 새 보호자로 교체하며, DB에서도 자녀당 현재 보호자 한 명만 허용한다. 기존 리포트 설정 조회는 유지한다.

최신 develop의 보호자 비밀번호·학부모 세션 잠금(V24), 공식 동의 문서(V25), 프록시 설정과 함께 동작하도록 통합했다. 기존 V1~V25는 변경하지 않고 이관 마이그레이션만 V26으로 추가했다.

## 체험

웹 주소: <http://127.0.0.1:5195>. Google 로그인 버튼을 누르면 이 환경에만 있는 합성 계정 선택 화면이 열린다. 실제 Google 계정·이메일 발송·결제 승인은 사용하지 않는다.

| 계정 | 가입 이메일 | 초기 자녀 |
|---|---|---|
| 보내는 학부모 | sender@example.test | 이관연습1, 이관연습2 |
| 받는 학부모 | receiver@example.test | 없음 |
| 자녀 3명 학부모 | full@example.test | 3명 |
| 추가 테스트 학부모 | spare@example.test | 없음 |

1. 보내는 학부모로 로그인하고 계정·탈퇴 관리에서 탈퇴 절차를 시작한다. 이관 페이지로 이동해 받는 학부모의 이메일을 찾는다.
2. 자녀·받는 계정·상담 포함 여부를 확인한다. 상담 체크박스는 처음에는 해제되어 있다. Google 본인 확인 팝업에서도 **현재 보내는 계정**을 선택하고, 원래 화면에서 완료 확인 후 요청한다.
3. 별도 시크릿 창에서 받는 학부모로 로그인한다. 자녀가 없어도 **받은 자녀 이관 요청 확인**으로 들어갈 수 있다. 보호자 동의와 본인 확인을 완료하고 수락한다.
4. 보내는 쪽은 이관 완료를 확인한 뒤 다시 탈퇴 절차를 진행한다. 남아 있는 다른 자녀는 기존 탈퇴 삭제 대상이므로 최종 화면을 확인한다.
5. 대기 중 탈퇴를 다시 시작해 **이관 유지**, **이관 취소 후 탈퇴 절차 진행**을 각각 확인할 수 있다. 취소만으로 탈퇴·삭제가 실행되지는 않는다. `full@example.test`를 찾으면 3명 한도 팝업이 나온다.

기존 개발 웹은 `localhost`, 이 환경은 `127.0.0.1`로 구분하여 refresh 쿠키가 섞이지 않게 했다. 학습·리포트의 외부 AI와 결제는 기존 E2E stub으로 대체하지만 서비스·DB·이벤트 흐름은 실제 코드를 실행한다.

## 실행과 되돌리기

저장소 루트에서 PowerShell로 실행한다.

```powershell
.\scripts\start_transfer_local.ps1
.\scripts\start_transfer_web.ps1
```

최초 프론트 의존성이 없으면 `frontend/web`에서 `npm ci`를 먼저 실행한다. 이미 빌드한 뒤 소스 변경 없이 재시작하면 `start_transfer_local.ps1 -SkipBuild`를 사용할 수 있다.

되돌릴 때는 다음 명령을 실행하고 기존 개발 환경으로 돌아간다.

```powershell
.\scripts\stop_transfer_local.ps1
```

이 명령은 **guardian-transfer-289 컨테이너와 이 저장소에서 실행한 5195 웹만 중지**한다. 웹의 실행 경로가 다르면 종료하지 않는다. 기존 `sagomungchi`와 이전 시제품 `guardian-transfer-local`의 컨테이너·DB·볼륨은 그대로이며, 테스트 볼륨도 보존한다. 이전 시제품의 V24 DB를 새 V26 환경에 재사용하거나 Flyway 체크섬을 강제로 수정하지 않는다.

완료된 이관을 되돌리는 사용자 기능은 이번 범위에 없다. 실험 DB에 예전 바이너리만 덮어쓰면 예전 삭제 로직이 이관 종료 표시를 모르므로, 롤백은 **격리된 실험 전체를 중지하고 원래 환경으로 복귀**하는 방식이다.

## 기존 구조와 접점

- 별도 Compose 프로젝트·볼륨·네트워크, loopback 포트만 사용한다. API 18095, 웹 5195, PostgreSQL 15495, Google stub 18096, learning 18097, AI 18098, report 18099, MinIO 19095/19096.
- 기존 V1~V25는 수정하지 않는다. V26에 이관 요청 테이블, `guardianship.transferred_at`, 학생당 LINKED 한 행 고유 인덱스, 재인증 목적 확장만 추가한다. learning/report 스키마와 학생 ID는 유지한다. SQL DEFAULT를 추가하지 않고 기존 스키마 규칙대로 INSERT에서 값·시각을 지정한다.
- 기존 중복 LINKED 데이터는 자동 삭제·덮어쓰기하지 않는다. migration이 실패하게 두어 별도 검토하도록 한다.
- 신규 API는 `APP_GUARDIAN_TRANSFER_ENABLED=true`, 화면은 `VITE_GUARDIAN_TRANSFER_ENABLED=true`일 때만 켜진다. 기본은 꺼짐이다. **플래그는 DB 되돌리기 수단이 아니다.**
- 이 브랜치의 GitOps local migration revision도 V26과 맞췄지만 클러스터에 적용하지 않았다. Compose·`.env.example`의 서버 플래그와 웹 플래그는 모두 기본 false다. 격리 테스트 실행 스크립트만 명시적으로 켠다.
- 계정→학생→이관 요청 잠금 순서와 한 트랜잭션으로 수락·취소·3명 한도를 직렬화한다. 동의·재인증 실패 시 연결 교체도 롤백한다.
- 이전 학부모의 이관된 연결은 삭제 권한·탈퇴 삭제 대상에서 제외한다. 선택한 상담은 새 학부모 소유로 바꾸고, 미선택 상담은 이전 학부모 탈퇴 시 그 소유분만 삭제한다.
- 구독·결제·환불은 명의를 바꾸지 않는다. 기존 탈퇴 사전 확인을 통과하고 대상 자녀의 활성 구독·진행 중 결제·환불이 없어야 요청·수락할 수 있다. 진행 중 분석이 있으면 수락을 보류한다.
- 학생 공개 설정과 리포트 기록은 유지한다. 학부모 전역 리포트 설정은 이전하지 않으며, 기존 ReportTemplateService 관련 #279 리팩터링 파일은 수정하지 않는다.
- 수락 시 기존 학생 세션과 기기를 해제한다. 새 학부모가 기기를 다시 등록해야 한다.

## 검증

검증 결과:

- 브라우저·HTTP 시나리오 11개 통과: 수락 전 접근 차단, 상담 포함·미포함 상태에서 이전 학부모 탈퇴, 동의 실패 시 트랜잭션 롤백, 취소와 늦은 수락, 동시 수락의 3명 한도, 수락/취소 경쟁, 활성 구독 재검사, 자녀 없는 학부모 수락, 실제 학습·리포트 보존, 합성 계정 선택·재인증.
- 실제 학습 기록·리포트 생성 후 이관하고 이전 학부모를 탈퇴시킨 다음, 새 학부모의 학습 원문 진입 버튼·리포트 목록·상세 본문까지 확인했다. 최종 화면 수정 뒤 해당 흐름과 수동 로그인도 다시 통과했다.
- 프론트 테스트 203개 통과. production build, 테스트 타입 검사, lint 통과. 기존 `AdminOperations.tsx`의 immutability 경고 1건은 이번 변경과 무관하며 유지했다.
- 계약 검사 전체 100개 통과(Python `-O` 실행). ERD에 이관 테이블·열·재인증 목적·인덱스를 반영하고 계약 검사도 함께 갱신했다.
- 백엔드 `gradle test bootJar`: 74개 클래스, 476개 테스트 통과(실패·오류·건너뜀 0). 이관 통합 테스트 11개에는 기존 보호자 비밀번호 복귀·세션 폐기·탈퇴 시 비밀번호 정리, 비밀번호/이관 재인증 목적 구분도 포함된다. Windows 공유 폴더의 파일 읽기 지연을 피해 컨테이너 내부 디스크에서 같은 소스로 실행했다.

- 별도 V25 DB에 합성 계정·보호자 비밀번호·잠긴 학부모 세션·GUARDIAN_PASSWORD 재인증·자녀 연결을 넣고 V26을 적용했다. 기존 행과 공식 동의 문서 3건이 모두 그대로 보존됐다.

## 팀 반영 전에 남는 결정

이관은 자녀별이며 수락 후 자동 탈퇴하지 않는다. 이관 대기 요청의 만료, 수신 알림 채널, 운영자의 복구 절차는 추가하지 않았다. 현재는 이관 페이지에서 5초 간격 갱신과 수동 새로 확인을 제공한다. 적용 전 기존 LINKED 중복 여부와 다른 브랜치의 V26 선점 여부를 확인한다. 대기 요청이 있는 상태에서 기능을 끄면 이관 화면에서 처리할 수 없으므로 요청을 먼저 정리해야 한다. 완료된 이관 기록의 삭제 보호는 기능 플래그를 꺼도 유지한다.
