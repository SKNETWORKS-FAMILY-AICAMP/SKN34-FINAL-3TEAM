# M2 글 점수 모델

학생 글을 받아 항목별 점수를 매기는 모델의 학습·평가 코드 (이슈 #4, 테스트·CI #142).
서빙(scoring-service)은 이 폴더 범위가 아니며, 여기서는 학습과 평가만 한다.

> AI Hub 원본·가공본·노트북·모델 가중치는 저장소에 넣지 않는다 (NFR-DAT-03). `.gitignore`로 막혀 있다.
> AI Hub 데이터는 외부 LLM API로 보내지 않는다.

## 서비스 반영 기준 (#228, 2026-11-02)

서술 3.0·논술 3.1을 사용한다. 논술 14출력 중 앞 3개(org·cont·exp)만 서비스로 보내며, `rawScores`는 소수 원점수, `scores`는 제공받은 경계로 변환한 정수다. 논술은 bisect_right 결과(0~3), 서술은 +1(hol 1~4·나머지 1~5)이다. 새 모델은 지시문을 입력에 넣지 않는다. 서비스 적용 대상은 서술·논술 모두 초5·6이다. scoring은 논술 초4·5·6 범위에서 승인 scope를 검사하지만 논술 미션이 초5·6만 게시되어 실제 논술 호출은 초5·6이다.

논술 경계는 모델 담당자가 전달한 임시값이며 품질 합격 기준이 아니다. 학습 스크립트의 산출물 저장 보완은 PR #261, 서비스 호환과 검증은 [#228 보고서](../../docs/report/ai.md#41-서술-30논술-31-서비스-호환-228)와 [API 4.3](../../docs/design/api-spec.md#43-scoring-service-호출-ai-learning-core)을 따른다.

## 최신 상태 (서술 3.0·논술 3.1)

| 항목 | 내용 |
|---|---|
| 모델 | `klue/roberta-base` 회귀. 서술 `m2-klue-narrative` 3.0, 논술 `m2-klue-essay` 3.1 |
| 입력 | **지시문 넣지 않음**(넣으면 문장을 외워 바꿔 쓴 문장에서 0.69 → 0.57). 서술 `[학년] 초5 [핵심어] …` + 글, 논술 `[학년] 초5 [글 종류] 주장` + 글 |
| 데이터 | 서술 AI Hub 71818, 논술 **AI Hub 545 에세이**(71819 대신: 채점자끼리 0.63 → 0.77). `clean_data.py`로 정제(`#@` 가림 표시·중복 제거, 학습·평가 걸친 중복 126묶음) |

| 평가 | AI Hub 검증용(VL), 학습에 안 쓴 글. 소수 예측 Pearson, 채점자 평균 대비 |

성능은 M2 담당자가 전달한 발표용 평가 결과([루트 README 6.3](../../README.md#63-m2-평가-결과와-해석)과 같음). 처음 보는 주제는 서비스 후보와 같은 설정으로 일부 주제를 빼고 학습한 평가용 모델에서 측정했다.

## 실행

```bash
cd ml/m2
uv sync

# 1) AI Hub 라벨 zip → 표 (zip은 풀지 않아도 됨, 원천 데이터는 읽지 않음)
uv run python scripts/build_tables.py \
  --descriptive-zip "<25.서술형 글쓰기 평가 데이터.zip>" \
  --essay-zip "<26.논술형 글쓰기 평가 데이터.zip>"

# 2) 문항 단위 분할 (시드 42, 이미 있으면 같은지 비교만 함)
uv run python scripts/split.py

# 3) 기준선
uv run python scripts/baseline.py

# 4) 파인튜닝 (GPU 있으면 자동으로 GPU, 없으면 CPU)
uv run python scripts/train.py --model klue/roberta-base
uv run python scripts/train.py --model xlm-roberta-base
#    동작 확인만: --limit 200 --epochs 1 --max-length 256

# 5) CPU 추론 속도
uv run python scripts/latency.py --model klue/roberta-base

# 6) 현재 최고 설정 (서술형, 입력에 문항 핵심어)
uv run python scripts/train.py --model klue/roberta-large --dataset descriptive --epochs 4 --lr 1e-5 --with-keyword
#    --train-prompts N: 공부용 문항을 N개만 씀 (문항 수 실험)
#    --save-preds: 답안별 예측을 checkpoints/<실험>/preds.npz로 저장 (앙상블용, 커밋 금지)

# 7) 앙상블 (저장한 예측 2개 이상을 평균)
uv run python scripts/ensemble.py --dataset descriptive --preds <preds.npz> <preds.npz>
```

모든 스크립트는 `--data-dir`, `--out-dir` 등으로 경로를 바꿀 수 있다 (로컬·RunPod 공통).

## 분할

같은 문항의 답이 학습과 평가에 섞이면 주제 단어를 외워 점수가 부풀려지므로 **문항 단위**로 나눈다.
AI Hub 원래 분할은 검증 문항이 학습에도 들어 있어(서술형 60/60, 논술형 89/90) 쓰지 않는다.

| | 방식 | 학습 | 검증 | 평가 |
|---|---|---|---|---|
| 서술형 | 학년×과목 20칸(칸마다 3문항)에서 1문항씩 빼고, 뺀 20문항을 바둑판 모양으로 검증·평가 | 40문항 (66.1%) | 10 (17.6%) | 10 (16.3%) |
| 논술형 | 글종류×학년 칸마다 앞 20% 평가, 다음 20% 검증 | 53문항 (53.2%) | 18 (23.3%) | 18 (23.4%) |

- 학년·과목·글 종류가 평가용에 고르게 들어가는지, 한 문항이 두 세트에 걸치지 않는지 확인함
- 평가용은 고정하고 마지막 성적에만 쓴다

**누수 확인**: 같은 TF-IDF+로지스틱 모델의 서술형 총점 QWK가 우리 분할 0.136, AI Hub 원래 분할 0.394.

## 지표

- **QWK**: 모델 vs 전문가1, 모델 vs 전문가2의 평균. 천장(전문가1 vs 전문가2)과 같은 조건으로 비교
- **균형정확도·과대·과소**: 정답 = 두 전문가 평균 반올림(3.5 → 4)
- 전체, 학년별, 글 종류별(논술형)로 보고

## 모델 입력·출력

- 입력(3.0·3.1): 지시문은 넣지 않는다. 서술 `[학년] 초{grade} [핵심어] {keyword}` + 글, 논술 `[학년] 초{grade} [글 종류] 주장` + 글. scoring-service API의 `grade`(정수)를 `초{grade}`로 바꿔 넣고, 핵심어는 문항 기준표의 M2 입력(`keywords`)을 쉼표로 이어 넣는다. 512토큰을 넘으면 앞+끝을 읽는다(#549, scoring 7장)
- 출력: 서술 9개 항목(총점 1~4, 나머지 1~5), 논술 3개 영역(구성·내용·표현 0~3)의 소수 회귀값. 정수 변환은 반올림 대신 `score_cuts.json` 경계로 하며 서비스도 같은 파일을 쓴다(`backend/scoring-service/metadata/1112b/`)
- 서술형·논술형을 따로 학습한다(`train.py --dataset descriptive` → `m2-klue-narrative`, 논술은 `train_545.py` → `m2-klue-essay`, API `inputType` `NARRATIVE`·`ESSAY`와 1:1)
- 주의: klue/roberta 토크나이저는 두 번째 문장에 `token_type_ids=1`을 붙이지만 모델은 0만 받는다. 추론할 때 `input_ids`, `attention_mask`만 넘길 것(그대로 넘기면 `IndexError`)

## CPU 추론 속도

글 1개, 토큰화 포함, 30회 (Intel 노트북 CPU, 4스레드, 2026-10-27, base·large 같은 PC에서 연달아 측정)

| 글 길이 | 토큰 수 | base 중앙값 | base 95% | large 중앙값 | large 95% | large/base |
|---|---|---|---|---|---|---|
| 200자 (서술형 수준) | 119 | 128ms | 143ms | 412ms | 438ms | 3.2배 |
| 650자 (논술형 평균) | 319 | 317ms | 381ms | 1,101ms | 1,281ms | 3.5배 |
| 1,200자 | 512 (최대) | 547ms | 587ms | 2,319ms | 2,825ms | 4.2배 |

- 10/26 base 측정(139 / 345 / 583ms)과 거의 같아서 이 PC의 측정 조건은 안정적이다
- large 첫 측정은 다른 프로그램이 CPU를 써서 95%가 중앙값보다 30% 가까이 높게 나와 버리고 다시 쟀다. 1,200자 줄은 다시 잰 뒤에도 95%가 중앙값보다 22% 높다
- 제안(서술형 large, 논술형 base)대로면 서술형은 글 1개에 약 0.4초, 논술형은 약 0.3초. 논술형까지 large로 하면 약 1.1초, 긴 글은 2.3초
- 속도는 모델 구조와 글 길이로 정해지므로 학습 전 모델로 잰 값이 학습 후와 같다

## 한계

- 평가 문항이 서술형 10개, 논술형 18개로 적다. 분할에 따른 변동 폭은 교차검증으로 따로 확인할 예정
- 데이터는 초5~중3, 서비스는 초3~6이라 M2가 실제 쓰일 학년은 초5·6이다
- 입력이 512토큰을 넘으면 학생 글 뒷부분이 잘린다 (논술형 최대 약 2,100자)
- 전문가끼리도 총점 QWK가 0.694(논술형 0.634)라 이보다 높이기는 어렵다. 판단 항목(연결성 0.453, 어휘 0.495)은 천장이 더 낮다
- 논술형 데이터에는 문항 핵심어가 없어 서술형에서 효과가 컸던 핵심어 입력을 못 쓴다
- 현재 방식에서 성능을 정하는 것은 문항 수(30개부터 평평)보다 문항마다 주는 기준 정보다. 더 올리려면 기준 정보를 늘려야 한다 (예: 선생님이 새 문항마다 몇 개를 먼저 채점해 보정, 채점 기준 설명·예시 답안)
