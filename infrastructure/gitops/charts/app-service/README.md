# app-service chart (#171)

One Helm release owns one Deployment and, where needed, a ClusterIP Service, HPA or KEDA ScaledObject, PDB, Ingress, NetworkPolicy, and a versioned migration Job. The six local releases use the values in `../../environments/local/`. The runtime commands and ports are the existing Dockerfile and Compose commands.

## Inputs and ownership

- Set `image.repository` with `image.tag` or immutable `image.digest`. Local `:local` images must be built and loaded into the `sagomungchi-local` kind cluster before sync. #186 publishes GHCR/ECR images and updates deployable tags or digests. The values do not imply published images.
- All releases target namespace `app`. The sole namespace-wide deny policy belongs to the core release; every app release also owns its narrower allow policy. The local Ingress exposes only core's `/api` path through class `nginx`.
- The `app/app-service-credentials` Secret is a prerequisite and is not created by this chart. Kubernetes cannot read a Secret from the `platform` namespace. Prepare the app namespace Secret from the same authorized source as the platform credentials, without checking values into Git or changing `platform/platform-data-credentials`.
- In the local `sagomungchi-local` cluster, `infrastructure/kind/create-app-secrets.ps1` prepares the app Secret (and the observability Secret when Grafana keys are set) from the repository root `.env` after checking the fixed context and node identity. `create-platform-secret.ps1` prepares the platform Secret from the same file.
- Required keys: `DB_USERNAME`, `DB_PASSWORD`, `RABBITMQ_USERNAME`, `RABBITMQ_PASSWORD`, `RABBITMQ_URL` (URL-encoded AMQP credentials), `INTERNAL_TOKEN`, `AUTH_JWT_SECRET`, `REPORT_DATABASE_URL`, `REPORT_ALEMBIC_DATABASE_URL`, `MINIO_ROOT_USER`, `MINIO_ROOT_PASSWORD`. `OPENAI_API_KEY` is optional for Pod startup but AI LLM calls fail without a configured provider and key. Local `REPORT_DATABASE_URL` uses the `report_db` database and `postgres.platform.svc.cluster.local`; the Alembic-only key doubles each URL-encoded `%` for its existing ConfigParser path. The report API and worker continue using the regular URL.
- The local report API signs download URLs for `http://127.0.0.1:19000`. To exercise a URL from the host, explicitly port-forward the local cluster's `platform/minio` Service from host port 19000 to service port 9000 while testing. This is a local test endpoint, not an EKS public storage URL.
- The platform Secret, RabbitMQ definitions, PostgreSQL databases, MinIO buckets, and PVCs stay under `platform-data` ownership. This chart neither creates nor mutates them. Platform namespace ingress deny and observability network policy remain separate work.
- For core and learning, `javaAgent.enabled` copies the pinned official OpenTelemetry Java agent JAR with an initContainer, then sets `JAVA_TOOL_OPTIONS` only in the chart. Their existing Gradle and application files are untouched. Local values export **metrics only** to Collector 4318; traces and logs are off because no trace backend is configured locally. The added image, startup work and JVM memory use require runtime measurement before production use.
- The AI image includes opt-in Langfuse v4 instrumentation. Keep `LANGFUSE_ENABLED=false` in local values while the Langfuse backend is unavailable. To enable it in an environment, set `LANGFUSE_ENABLED=true`, supply `LANGFUSE_PUBLIC_KEY` and `LANGFUSE_SECRET_KEY` from an app namespace Secret, set `LANGFUSE_OTLP_ENDPOINT` to the Collector's full OTLP/HTTP `/v1/traces` URL, and set `networkPolicy.egressToCollector=true`. The Collector trace pipeline and authenticated Langfuse exporter must also be enabled in that environment. The AI SDK records call type, prompt version, model, token counts and error code; it does not pass prompt text, answer text or student identifiers to observations. Missing keys or endpoint fail startup when enabled.

## Migration and scaling

- The core and learning Flyway Dockerfiles in `../../migrations/` copy the service's existing SQL into a dedicated image. Their local image tags and the report Alembic image must match the app revision. `migration.revision` changes only when migration files change. A PreSync NetworkPolicy at wave -2 permits DB access before the PreSync Job at wave -1, including later syncs under app default deny. The named Job is retained after success; the chart does not run migrations at application startup or automatically downgrade a database.
- `report-api` uses the report image's normal Uvicorn entrypoint and always keeps at least one replica. `report-worker` uses `python -m app.worker`, consumes `report.report.generate` and `report.student.deleted`, and has KEDA 0–1 with prefetch 1 in local values. Increase the maximum only after measuring LLM request capacity.
- Local HPA and PDB are disabled for single-replica resource checks. The templates support the product deployment target, but metrics-server, capacity and multi-replica behavior need separate verification. Do not use both HPA and KEDA on one Deployment.
- Core's local 15-second preStop and 180-second termination grace are starting values against its existing SSE executor/timer budget. Verify the rolling termination path before treating these as sufficient.

## Current verification boundary

Apply these values to the `sagomungchi-local` kind cluster with explicit Kubernetes context, releases and namespace. The platform-data PVCs and Secret in that cluster stay under `platform-data` ownership. The local values omit unimplemented LLM and Toss stubs, so those outbound calls remain denied by the app policy. A successful chart render does not demonstrate readiness, HPA/KEDA behavior, telemetry ingestion or an end-to-end request.
